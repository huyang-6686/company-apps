# 镇安县生态产业协会管理中台实施计划 v1.0

状态：阶段 7 编码实现（2026-10-20 更新）；基础实施仍依据设计文档 v0.3.2、页面基线 v1.1、需求澄清增补与 Harness 复评处置记录；2026-10-20 起新增任务、统一通知和接口接入范围，强制以与光工作中台 2026-10-19/20 正式规范及接口合同为准。本计划只定义实施顺序和边界，不把未确认的平台参数写入生产配置。

## 0. 已定案与待确认输入

已定案：

- 支出审批：飞书和钉钉都同步到与光工作中台后分流到本应用；应用只接收结果。
- 保管期限：永久，`retention` 字典初始化 `permanent`，不设到期清理。
- 部署：飞书开放平台，使用飞书自带能力（含附件病毒扫描），不引入第三方扫描服务。
- 规范：按 2026-10-19 最新版三份送审稿执行，状态保持“送审稿”标注。

待确认（不阻塞本地契约测试，阻塞对应功能上线和生产通知/任务接入）：

- 理事单位会费档位（1000/2000）理事会书面确认。
- 年中入会会费折算规则。
- 钉钉审批模板 ID 与审批人映射。
- 与光分流字段、权限下发协议、回调验签规则。
- 飞书用印模板与回调参数。
- 与光正式 `application_id`、模块 ID、应用负责人和接口联调负责人。
- 与光任务/通知 API 基地址、请求签名公钥或密钥配置、回调地址登记。
- 轻立方租户本应用飞书机器人配置、测试账号和联调环境。
- 统一员工 ID 与轻立方/与光租户 `feishu_user_id` 的核验映射。
- 本应用可接收的三类任务及模块范围确认。

处理方式：代码内以配置占位 + 显式枚举实现，未确认参数不进入生产配置文件；对应页面/接口在联调阶段前完成注入，不阻塞其他模块开发。

## 1. 工程目录与模块边界

单仓库 TypeScript，Next.js 一体化：

```text
app/
  (auth)/            登录、飞书授权、补充账号
  (workspace)/       工作台与业务页面（严格按页面基线路由）
  api/               服务端 API 与 webhook
modules/
  membership/  finance/  projects/  brand/  archive/  hr/  admin/
  shared/            权限、审计、通知、外部集成、网盘客户端
jobs/               worker 与 cron 入口
db/                 Drizzle schema 与迁移
tests/              单测、集成、E2E
infra/              飞书开放平台部署配置、环境模板（不含密钥）
```

模块规则：页面只调用本模块服务层；跨模块读写走 shared 服务接口；webhook 只做验签、幂等和入队，不写业务表。

## 2. 数据库表与迁移顺序

按依赖顺序分批迁移：

1. 基础：`tenant`、`person`、`member_unit`、`permission_resource`、`permission_binding`（与光下发镜像）、`audit_event`、`notification_log`。
2. 会员：`fee_standard`、`fee_bill`、`fee_payment`、`fee_arrears_view`、`external_form_link`、`external_form_submission`。
3. 财务：`finance_entry`、`expense_application`、`oa_instance`、`oa_flow_type` 枚举（expense/seal/leave/other）。
4. 项目/品牌：`project`、`project_execution`、`activity`、`activity_review`、`brand_authorization`、`brand_product`、`member_service_record`。
5. 档案：`archive_record`、`archive_task`、`archive_file`（网盘元数据）、`archive_borrow`、`archive_transfer`、`archive_recycle_item`、`compliance_inspection`、`compliance_material_pack`、`compliance_rectification`。
6. 人事/行政：`hr_employee`、`attendance_record`、`leave_instance`、`administrative_matter`。
7. 运维：`outbox_event`、`webhook_event`、`integration_config`（密钥走平台密钥管理，配置表只存引用）。

迁移规则：每批一个迁移文件，先枚举/字典后业务表，外键跨批引用用延迟约束；`retention` 初始化为 `permanent`；跨租户序列按 `tenant_id + category + year`。

## 3. 登录、租户与权限接入

- 登录：飞书 OAuth（主路径）+ 补充账号密码（自适应哈希、失败锁定、会话到期/吊销/空闲过期）；会话时长待安全配置确认，默认值写在配置模板不写死。
- 租户：当前仅轻立方；租户谓词由服务端从已验证会话注入，客户端参数不能扩大范围。
- 权限：与光项目角色（负责人/经办人/成员/支持/观察人）映射到 `permission_resource` 动作与 `data_scope`（tenant/project/assigned/self），缺失或未知绑定默认拒绝；S03 页面只读查询绑定与审计，不提供授予/回收动作。
- 敏感字段按最小返回；导出必须过资源动作 + 范围 + 字段白名单校验并写审计。

## 4. 与光、权限、审批和 API 接口接入

- 同步链路：飞书组织/审批 + 钉钉审批 → 与光工作中台 → 本应用 webhook。
- 本应用注册的 webhook：验签失败拒绝入队；按 provider + flow_type + event_id 幂等；重放窗口/限流在接口确认单确定前使用保守默认值并标注可调；过期事件进隔离队列，管理入口 S07 可见失败原因。
- 组织同步（S02）：定期拉取与光项目节点与成员，写同步批次记录；不建协会部门树。
- 权限绑定（S03 镜像）：与光下发后写 `permission_binding`，保留历史批次用于审计。
- API 客户端：与光接口封装在 `shared/yuguang/`，字段映射集中在单一配置对象，便于上线后反向扫描飞书时一次性优化。

## 5. 钉钉支出审批和飞书用印接入边界

- 支出（expense）：钉钉审批 + 飞书审批都经与光分流；应用只读镜像节点/意见到 `expense_application` 与 `oa_instance`，不提供审批按钮，不得编辑审批事实；回流草稿仅在本地字段（金额、用途、附件关联）可改。
- 用印（seal）：飞书 OA 承载，经与光同步回 `oa_instance`；F04 页面只读展示镜像与回流状态。
- 请假（leave）：飞书审批，经与光回流后回写考勤（H03）。
- 边界：所有外部审批状态变更只经 webhook 入队 → worker 消费，禁止 API 内同步写审批表；模板 ID、审批人映射待确认项以 `integration_config` 占位。

## 6. 外部会员表单和附件临时区

- M07 公开表单：仅有效令牌可访问；令牌摘要落库，原文不落库；7 天有效、可撤销/锁定、20MB/10 附件、限频与失败锁定按已确认参数实现。
- 附件先入临时区（飞书网盘临时目录），使用飞书自带病毒扫描；扫描失败、超限、重复提交拒绝正式归档并通知运维（S07 可见）。
- 核验通过后由 worker 转正式网盘并回填 `archive_file` 元数据；临时区默认保留 30 天，过期清理走 cron 并留审计。

## 7. 网盘归档和文件元数据

- 路径：中台网盘/3. 业务部/1. 项目部/2. 镇安生态产业协会管理中台；2/3 级目录配置化。
- 文件名按六类模板配置生成并校验版本、日期；`retention` 恒为 `permanent`。
- `archive_file` 保存外部文件 ID、路径、checksum、大小、mime、版本、权限引用；应用不存文件内容。
- 回收站（A09）：软删除 + 网盘同步状态 + 恢复 + 到期清理（cron）；借阅/移交（A08）记录状态迁移与经办留痕。
- 网盘 PoC（上传、签名 URL、版本、路径创建）为 W1 档案模块前置条件，PoC 未过不进入该模块编码。

## 8. worker、cron、webhook、outbox

- webhook：仅验签、幂等去重、入队，返回快速。
- worker：消费 outbox/webhook 队列，处理审批镜像、文件归档、通知发送、组织同步落库；失败重试上限后进死信并告警。
- cron：临时区清理、归档任务超期提醒、同步批次调度、通知重试；全部幂等，可安全重跑。
- outbox：业务表变更同事务写 `outbox_event`，worker 异步外发（如向与光回执），保证至少一次投递 + 幂等消费。

## 9. 测试、验收、部署和回滚顺序

测试：

1. 单测：枚举校验、状态机、文件名模板、权限谓词、令牌摘要。
2. 集成：webhook 幂等/验签/隔离队列、outbox 投递、临时区→归档链路。
3. E2E：页面基线逐页路由可达 + 权限拒绝路径；四级菜单无第五级断言。

验收：以 `PROJECT-MENU-PAGE-BASELINE.md` 逐行勾选；每个 P 级页面附权限资源码验证记录。

部署顺序（飞书开放平台）：

1. infra 配置评审 → 2. 数据库迁移（批 1→7）→ 3. W1 后端（权限、组织同步、webhook）→ 4. W1 页面（P00、M01-M07、F01-F04、A01-A04、A08-A09、S01-S07）→ 5. W2 页面 → 6. W3 页面 → 7. 联调（注入已确认外部参数）→ 8. 验收 → 9. 上线。

回滚：每批次迁移配对应回滚脚本；应用回滚到上一镜像版本；webhook 隔离队列保证回滚期间事件不丢失、恢复后重放。

## 10. 菜单硬约束落点

- 所有路由按页面基线 v1.1，1 级业务大类 / 2 级模块工作 / 3 级事项工作 / 4 级科目工作；四级页面内部只用标签、筛选、状态视图、操作区和弹窗。
- E2E 断言：导航树深度 ≤ 4；无隐式五级（四级页面内不得出现子导航组件）。
