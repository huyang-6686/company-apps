# 镇安县生态产业协会管理中台设计文档

状态：阶段 6 实施计划编写中（2026-10-19）；设计基线 v0.3.2，部署/保管期限/病毒扫描已定案

## 1. 设计基线

- 交付方式：按需求重新开发，不搬运旧工程。
- 技术路线：全栈统一 TypeScript 单仓库。
- 应用架构：归入公司第四层“业务层-大项目”；具体工程采用 Next.js 一体化，页面、服务端 API 和任务调度在同一工程内按模块组织。
- 数据层：PostgreSQL + Drizzle ORM。
- 文件边界：文件存网盘，应用只保存档号、路径、版本、权限和关联对象元数据。
- 菜单边界：工作台 + 6 个一级业务大类 + 独立管理入口；层级固定为 1 级业务大类、2 级模块工作、3 级事项工作、4 级科目工作，禁止第五级及等价导航结构。四级页面内部只用标签、筛选、状态视图、操作区和弹窗。
- 正式依据：组织架构管理规范 v1.0、应用搭建结构规范 v1.1、网盘映射管理与文件命名规范 v3.2（均为待创始人审核确认的送审版本），以及已确认需求、实现基线和运营版菜单建议；三份规范作为复核基准，不在本项目内重写。
- 审批边界：应用内不做审批。支出审批确认结论（2026-10-19）：飞书和钉钉的审批都同步到与光工作中台，再由与光分流到本应用；应用只接收结果。会员单位不进入飞书/钉钉，入会使用外部信息录入表单，不视为 OA 审批。

## 2. 首期模块边界

本应用是公司“业务部 → 项目部”承接的特大项目专项管理，项目为“镇安县生态产业协会管理中台”；协会不是公司组织部门，不建立协会专属部门树。“镇安真味区域公用品牌项目运营”是同一组织路径下的另一个独立大项目，两个项目不合并；本设计只覆盖协会管理中台项目。

业务大类：会员与组织、财务与资金、项目与活动、品牌与会员服务、档案与合规、人事与行政；六类首期全部建设，按实施波次交付。

独立管理入口：补充账号、组织同步、权限审计查询、钉钉/轻立方集成、审计记录、固定枚举和系统参数。该枚举说明功能范围，具体层级以页面基线 S01-S07 为准；权限审计仅只读查询与光下发绑定及数据范围，不在本应用授予、回收或修改授权。

每个一级大类均进入首期建设。具体事项的审批规则、展示字段和外部接口参数在实现前按本文件和接口确认单冻结。

## 3. 应用分层

```text
app/
  (auth)/                 登录、飞书授权、补充账号密码登录
  (workspace)/            工作台和业务页面
  api/                    服务端 API 与 webhook
modules/
  membership/             会员、入会、会费、欠费
  finance/                收支、支出审批、报表
  projects/               项目、活动、预算、结项
  brand/                  授权企业、产品、会员服务
  archive/                档案、归档任务、网盘元数据、迎检
  hr/                     人员、考勤、请假、行政
  admin/                  账号、组织、权限、审计、集成
db/
  schema/                 Drizzle 表结构
  migrations/             数据库迁移
lib/
  auth/ policy/ audit/    跨模块基础能力
jobs/                      年度账单、提醒、同步、归档任务
```

目录是目标工程结构，不是现有源码目录；实现时可按 Next.js 版本调整，但模块边界必须保持。审批动作、组织主数据和权限标准不在本工程内自建。

## 4. 核心数据模型

### 4.1 身份与组织

- `tenant`：应用接入的租户范围；当前仅开放轻立方租户，应用层级高于租户，业务人员全部来源于轻立方租户。
- `department`：与光提供的项目组织归属或协作范围映射；本项目不建立协会专属部门树。
- `person`：统一人员主键，供账号、员工、申请人、经办人和归档责任人引用。
- `user_account`：飞书/钉钉/补充账号映射，记录类型、有效期和状态。
- `external_account`：provider、external_id、union_id 和映射状态。
- `account_department`：账号与业务部门的关联，补充人员虚拟部门单独标记并排除在协会组织统计外。
- `login_session`：会话、吊销时间、过期时间和设备摘要。
- `permission_binding`：统一权限标准下发的资源、动作和数据范围，不在业务模块自定义角色。
- `permission_resource`：1-4 级菜单资源码与动作注册表。
- `permission_sync_log`：与光权限下发批次、结果、错误和重试信息。

### 4.2 会员与会费

- `member_unit`：会员单位主数据，统一社会信用代码唯一。
- `membership_application`：入会申请、钉钉实例号、审批状态和回流草稿。
- `external_form_link`：令牌摘要、有效期、撤销/锁定状态、失败计数、限频窗口和创建/解锁审计；令牌原文不落库。
- `external_form_submission`：会员单位外部表单提交、提交编号、校验状态、补正状态、来源链接 ID 和提交时间。
- `external_form_attachment`：外部表单附件的临时存储引用、扫描状态、网盘归档状态和关联对象；核验通过前只在临时区，核验通过后才写入正式网盘；提交后默认保留 30 天，过期自动清理并保留审计记录。
- `membership_position`：会员类型与任职身份关联。
- `fee_standard`：身份档位、年度、金额、生效日期、表决附件元数据。
- `fee_bill`：会员单位 + 年度唯一的应收账单。
- `payment_record`：缴费核销记录，支持部分缴清、多笔缴费和凭证元数据。
- `payment_allocation`：缴费与账单的分摊关系，支持跨笔、跨年度校验。
- `collection_contact`：催缴方式、时间、结果、备注和经办人。
- `member_change`：入会、变更、退会、除名的状态迁移和依据。

### 4.3 财务、项目与活动

- `finance_entry`：收入/支出流水，金额使用 decimal，来源和关联单据可追溯。
- `expense_application`：支出申请、外部审批节点/意见的只读镜像、附件元数据和回流草稿状态；应用不得编辑审批事实。
- `oa_instance`：外部流程类型、实例号、来源事件号和当前状态；外部实例号 + 流程类型唯一。
- `oa_flow_type` 固定枚举：`expense`（支出）、`seal`（用印）、`leave`（请假）、`other`（其他）；载体映射按当前决策和平台确认单配置，钉钉例外待创始人确认。
- `oa_event`：回调摘要、验签结果、时间窗、重放标记和处理状态。
- `outbox`：回流、同步、提醒等异步任务的幂等键、重试次数、下次重试时间和错误摘要。
- `project`：项目基本信息、预算、负责人、状态和结项信息。
- `project_milestone`：项目阶段、计划/实际日期、状态和风险。
- `activity`：活动计划、执行、成效、费用和归档关联。

### 4.4 品牌、人事、档案

- `brand_authorization`：授权主体、产品范围、期限、状态和授权文件。
- `product`：产品主数据、分类、展示状态和网盘图片元数据。
- `authorization_product`：授权企业与产品的多对多关系，支持到期下架。
- `member_service_record`：会员服务和参与记录。
- `administrative_matter`：行政事项类型（印章、会议、采购、资产）、业务字段、外部引用和本地跟踪状态；不承载审批动作。
- `inspection_record`：检查台账、结论、问题和责任人。
- `inspection_material_pack`：检查材料包、目录、版本和生成状态。
- `rectification_item`：整改问题、期限、责任人、佐证和销号状态。
- `employee`：工作人员、部门、岗位和在职状态。
- `attendance_record`：月度考勤汇总和异常。
- `leave_request`：请假申请、审批状态和考勤影响。
- `archive_record`：档号、题名、责任者、日期、分类、密级、保管信息和关联对象。
- `archive_task`：自动/手动归档任务、截止日期、提醒和完成状态。
- `file_metadata`：网盘路径、文件版本、校验信息和访问范围，不保存文件二进制。
- `notification_outbox`：提醒目标、模板、投递状态和失败原因。
- `dictionary_item` / `system_parameter` / `integration_config`：固定枚举、系统参数和外部集成配置引用。
- `archive_borrow`：借出、到期、归还及状态迁移。
- `archive_transfer`：移交双方、时间、清单、确认状态和经办留痕。
- `archive_recycle_item`：删除申请、网盘同步结果、恢复状态、到期清理时间和审计引用。

### 4.5 通用约束

- 所有业务表带 `tenant_id`、创建/更新时间、创建人和软删除标记。
- 所有业务单据引用 `person_id`，不以姓名字符串作为责任人主键。
- 金额使用 PostgreSQL `numeric(14,2)`，禁止浮点金额；时区统一 `Asia/Shanghai`。
- 业务状态使用显式枚举，状态迁移由服务端校验。
- 重要变更写入只追加的 `audit_event`，记录 trace_id、主体、动作、脱敏前后值摘要、操作者和保留期限。
- `member_service_record` 字段：`tenant_id`、`member_unit_id`、`service_type`、`subject`、`description`、`occurred_at`、`participants`、`owner_person_id`、`related_project_id`、`archive_record_id`、`created_at`。
- 软删除不绕过业务唯一性；信用代码、账单、档号使用有效记录唯一索引，档号使用数据库序列和唯一约束。

## 5. 关键业务流程

### 入会信息收集与确认

1. 协会生成一次性或可配置有效期的外部表单链接，发送给会员单位；链接不要求会员账号登录。
2. 会员单位在线填写单位、联系人、任职信息并上传附件；不要求进入飞书或钉钉，附件先进入临时区。
3. 附件清单采用固定必填 + 可选补充：营业执照、资质/许可证、法人身份证明、法人/负责人简历、入会申请书为固定必填；其他材料可选。应用校验链接、必填项、附件完整性和重复提交后，创建 `external_form_submission` 与 `membership_application`，并返回提交编号。
4. 协会运营人员在应用内执行资料核验、补正和确认；这不是 OA 审批流，状态为 `submitted → needs_correction/submitted → member_draft → active`。
5. 确认后写入 `member_unit` 和 `membership_position`，将核验通过附件归档到正式网盘并创建档案任务；不合格/重复附件不进入正式档案；表单提交以 submission_id 幂等。

### 年度会费

1. 外部 cron 触发年度任务，按租户 + 年度获取分布式锁，读取当时生效的 `fee_standard`。
2. 为生成时在册会员创建 `member_unit + year` 唯一账单；年中入会按规则配置是否全额/折算，规则未定前禁止自动折算。
3. 登记缴费写入 `payment_record` 和 `payment_allocation`，事务内更新账单实缴汇总和会员欠费状态。
4. 欠费视图按应收、实缴、`due_date` 和催缴记录实时计算；重复执行只补缺，不覆盖人工核销。

### 支出审批

1. 应用创建支出申请并提交甲方钉钉审批；审批人和节点由钉钉模板/与光维护。
2. 通过/驳回动作在钉钉完成，应用页面只读展示状态镜像。
3. 钉钉 → 与光分流 → 应用，回流后生成锁定审批金额、类别和项目的流水草稿。
4. 财务人员确认草稿，才生成生效的 `finance_entry`；不得借确认修改审批事实。
5. 驳回、撤回或重复事件不得产生生效流水；失败进入 outbox 重试。

### 档案归档

1. 入会通过、审批通过、项目结项等事件创建归档任务。
2. 任务完成后通过数据库序列生成年度-类别-序号档号并登记著录。
3. 文件按配置化路径模板上传正式网盘，回填外部文件 ID、路径、checksum、大小、mime、版本、保管期限和权限元数据。
4. 删除进入应用回收站并同步网盘删除，应用保留 30 天；失败进入 outbox，所有删除和权限变更写审计。
5. 借阅、移交、归还形成独立记录，不能只改档案状态。

## 6. 权限与登录

- 统一登录页：飞书用户走飞书授权，补充账号走密码登录。
- 补充账号挂在“补充人员”虚拟部门，带有效期，到期自动回收，管理员可续期。
- 外协人员不属于本应用范围；本应用当前仅由轻立方租户员工推进。与光租户中的外协人员（咖啡厅）参与望向山工作，不纳入本项目组织、权限或数据范围。
- 长期协作者使用部门级数据范围；临时访客使用指定模块范围。
- 页面隐藏只作为体验优化，所有 API 必须二次校验租户、资源、动作和数据范围。
- 飞书通讯录 → 与光工作中台 → 本应用；组织和权限由与光工作中台提供，本应用不另建平行组织架构。
- 与光工作中台提供组织、权限、审批、跨应用交换和 API 接口；会员、会费、财务、项目、档案等协会业务数据由本应用管理。
- 财务、会员、档案的敏感字段按权限返回，导出操作必须记录审计事件。

### 与光应用角色映射（不创建本地角色）

| 与光项目角色 | 本应用资源动作 | 数据范围 |
| --- | --- | --- |
| 项目负责人 | 项目范围内模块读取及经授权新增/更新/确认 | 与光下发的项目数据范围 |
| 经办人 | 被分配事项读取及经授权新增/更新 | 与光下发的事项/项目范围 |
| 成员 | 被授权页面读取及本人负责事项操作 | 与光下发范围 |
| 支持（人力、行政、财务、法务） | 对应支持模块读取/办理，不默认获得其他模块 | 与光下发的支持范围 |
| 观察人 | 只读 | 与光下发范围 |

本表是资源映射约束，不是本地角色定义；实际资源动作和范围以与光权限下发为准，缺失或未知绑定默认拒绝。

### 数据范围与异常处理

- `data_scope` 仅允许 `tenant`、`project`、`assigned`、`self`；接口查询必须从已验证的 permission_binding 注入租户及范围谓词，客户端参数不能扩大范围。
- 个人身份材料、联系方式按最小字段返回；身份证件等高敏原文仅按授权读取，日志只记脱敏摘要，不默认导出高敏字段。数据库列加密方式待密钥平台确认后定稿，未确认前不存不必要的证件原文。
- 导出必须校验资源动作、范围和字段白名单，并写导出审计事件，记录筛选摘要、行数、操作者和时间。
- 补充账号口令只保存经验证的自适应哈希；失败按配置阈值临时锁定并审计；会话具备到期、吊销和空闲过期校验，具体时长待安全配置确认。
- webhook 验签失败拒绝入队；按 provider + flow_type + event_id 幂等；重放窗口和限流阈值在外部接口确认单/部署配置中确定，不得未知放宽；重复事件返回已处理结果，过期事件进入隔离队列。
- 外部表单失效、撤销、锁定、超限附件、扫描失败、重复提交均拒绝正式归档并在管理入口写明原因；失败通知必须可见。
- 文件名从公司网盘规范六类模板配置生成，校验事项名、主/次版本与日期；`retention` 仅允许经确认的保管期限字典取值。跨租户文件编号按 `tenant_id + category + year` 隔离。

## 7. 外部集成契约

### 轻立方/飞书/与光

- 输入：与光提供的账号身份、租户标识、业务部门、成员、权限批次和 API 接口数据；当前应用租户接入白名单仅为轻立方。
- 输出：本地账号映射、组织/权限同步日志和失败重试任务；补充账号由轻立方发放/重置/回收，本应用只存映射、有效期和状态。
- 组织统计排除“补充人员”虚拟部门，业务单据仍绑定统一 `person_id`。
- 项目角色由与光授权，至少覆盖项目部负责人、项目负责人/经办人以及人事、财务、行政等协作人员；本应用不另建角色体系。
- 未确认：真实授权端点、字段名、回调签名方式，接入前必须取得平台接口确认单。

### OA 与外部表单（钉钉/飞书/会员链接）

- 支出审批：当前已确认业务决策为甲方钉钉 → 与光 → 应用；应用不提供审批按钮，只接收结果。公司应用规范送审稿与此存在载体冲突，例外是否保留待创始人确认；确认前仅保留可配置占位，不固化生产载体参数。
- 运营团队用印：首期接入飞书用印，正式流程由飞书 OA 承载，并经与光同步回应用；不得与会员入会外部表单混为入会审批。本应用只同步、分析、展示和留痕。
- 会员入会：外部表单链接 → 应用表单接收 → 协会运营人员资料确认，不进入飞书/钉钉审批。
- OA 回流必须幂等，以外部实例号 + 流程类型唯一，并保留 `source_event_id`、验签结果和重放标记；外部表单以 submission_id 幂等。
- 外部表单内置于本应用实现：页面、一次性链接、校验和临时附件由镇安应用闭环处理。
- 默认链接有效期 7 天，过期后由运营人员重新生成链接；支持手动撤销。
- 附件上限（已确认）：单个附件 20MB，单次提交最多 10 个。
- 反滥用（已确认）：同一 IP/设备对同一链接限频提交，失败次数超限后锁定该链接，由运营人员解锁。
- 未确认：镇安支出审批载体例外确认、钉钉模板 ID、与光字段、回调签名/验签规则、飞书用印模板与回调参数。

### 网盘

- 输入：文件路径模板、版本、权限、关联对象、provider 和外部文件 ID。

## 8.1 部署与运行基线

- 环境：dev、staging、prod 三套隔离配置；生产仅通过受控发布迁移。
- 运行时：首选容器化 Node.js 长驻进程，Next.js Web、worker 和 webhook 分进程部署，共享同一模块代码。
- 数据库：PostgreSQL 连接池，迁移由 CI/CD 执行；禁止应用启动时隐式改表。
- 任务：外部 cron 触发 worker；年度账单、提醒、同步补偿和网盘删除分别使用租户/业务键幂等，并通过 outbox 重试。
- 临时附件清理：以 submission_id + attachment_id 幂等，提交满 30 天且未归档/未被保全时清理临时文件，记录清理原因、任务和结果；运营人员可在保全状态下暂停清理。
- webhook：公网 HTTPS 独立入口，快速验签入队后返回 200；限流、重放缓存和失败告警必需。
- 运维：集中日志和 trace_id、错误/队列/任务指标、失败告警；PostgreSQL PITR 与网盘元数据备份，目标 RPO/RTO 在实施计划确认。
- 密钥：仅使用部署平台密钥管理，代码和配置模板不保存密钥。
