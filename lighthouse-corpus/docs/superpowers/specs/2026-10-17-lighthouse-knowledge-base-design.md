# 灯塔知识库独立重建设计方案

日期：2026-10-17  
状态：19 项原始需求决策已确认；第 20 项按用户“完成第五阶段”指示确认修订稿作为实施计划基线  
范围：在与光体系第三层工具层建设灯塔知识库，归口租户轻立方；不合并为与光工作中台模块，不迁移或拼接豆包旧代码。

## 1. 目标与原则

灯塔知识库首先服务创始人的个人知识资产和个人检索，沉淀近十年历史资料、创始人日常分享、行业情报和员工知识贡献。员工检索和贡献是次级能力，首页以创始人工作台和深空观测站式全息知识节点为核心展示。

设计原则：

- 以扫描、解析、索引和权限过滤形成可追踪的知识资产，不把旧系统代码当作新系统基础。
- 归档、迁移、删除和应用建议与实际执行分离；系统只提供清单和方案，实际迁移/删除操作由创始人根据清单自行执行，整个体系不引入飞书 OA 审批环节。
- 事实、来源、模型推测和未知状态分开保存；解析失败时不生成虚假内容。
- 与光工作中台角色是员工业务授权的唯一来源。飞书身份只用于识别用户和承载交互。
- 先在一个 PostgreSQL 上叠加能力；先做全文检索，精读稳定后再加 pgvector，图谱和 Ontology 后置。
- 遵循《应用搭建结构规范》：工具层应用只消费工作台下发的角色权限标准、组织架构和分流数据；整个体系不参与飞书 OA，迁移/删除由创始人按清单自行操作；所有大模型调用经工作台总接口。

### 1.1 独立重建落点与代码主权（新增，关闭 B1）

本项目采用全新独立的工具层应用、部署和数据层，归口租户轻立方；旧灯塔应用仅作为历史证据和过渡期参照。独立重建明确意味着不复用旧表结构、旧服务层、旧路由、旧硬编码凭据或豆包旧代码，不把灯塔并入与光工作中台。

- 新应用必须可独立导出：版本化 schema DDL、脱敏配置、全量数据导出格式和审计字段说明均归档到可读文件。
- 旧应用在过渡期保持只读和原有推送/扫描任务运行；新应用通过独立入口验证，连续稳定后再切换任务。
- 旧接口不作为新系统契约；已发送卡片需要的 daily-news 等兼容入口是否保留，列入接口清单，未确认前不删除。
- 灯塔仅通过与光工作中台批准的接口接收数据，不直接读取其他应用数据库；跨租户资料接入须先由工作台分流，不由灯塔持有另一租户的应用权限或凭据。
- 新旧系统不双写生产数据；双轨期间分别运行并对账，切换窗口由创始人确认，失败时恢复旧任务。

## 2. 用户与权限

### 2.0 身份、角色权限与组织架构来源（按正式规范修订）

灯塔是租户轻立方下的工具层应用，飞书通讯录是组织架构唯一源头，先同步至与光工作中台，再由工作台向灯塔下发标准。灯塔不维护第二份组织架构主数据，不自建角色或权限体系。

- 用户身份使用轻立方飞书身份；组织、员工和角色关联以工作台下发数据为准，不由灯塔自行建立跨租户 open_id 到员工号的授权映射。
- 灯塔只执行工作台下发的权限标准，对内容字段、检索、引用、附件和导出执行访问检查；2.4 的敏感分级是内容分类与处理规则，不构成灯塔自定义角色或授权标准。
- 工作台接口路径、字段、鉴权、版本、失效时限和 SLA 均须依据批准的接口契约接入；未取得契约前保持 unknown，不自行假设事件频率、缓存 TTL 或重试参数。
- 授权数据不可用或无法确认有效性时，灯塔不得放行无法证明有权的员工请求，并记录拒绝原因。任何应急访问仍须使用工作台正式下发的权限标准，不设置绕过工作台的本地管理员、白名单或恢复口令。

### 2.1 创始人

创始人可提出扫描、配置、监控、归档、迁移、删除和应用建议等业务操作；实际可用功能按与光工作中台下发的权限标准执行，灯塔不自行定义创始人角色或授予绕过权限。创始人分享必须经过追问和明确确认后才归档；“归档”和“应用”可以分别发生。

### 2.2 员工

通过飞书私聊机器人进行工作检索或提交知识贡献。员工可执行的操作由工作台下发权限标准控制；灯塔不定义员工角色。员工贡献进入贡献箱，经自动解析、去重、分类、质量评估后等待授权审核人处理。

### 2.3 失效身份

工作台下发的身份/权限标准缺失、失效或不可验证时，灯塔拒绝无法证明有权的请求，不沿用过期数据，也不返回受限字段。拒绝原因和标准版本写入审计。灯塔不自行定义角色同步周期、快照 TTL 或失效传播 SLA。

### 2.4 敏感分级与字段级处置矩阵（新增，关闭 I6）

所有知识节点执行四级内容敏感分级：公开、内部、受限、私属。该分级用于描述内容和执行脱敏规则；员工身份、角色以及最终授权仍完全由工作台下发标准决定。

| 级别 | 默认字段处理 | 授权依据 | 导出处理 |
|---|---|---|---|
| 公开 | 可展示全部字段 | 工作台下发标准 | 按工作台标准执行并审计 |
| 内部 | 不额外脱敏 | 工作台下发标准 | 按工作台标准执行并审计 |
| 受限 | 默认隐藏正文、附件和引用 | 工作台下发标准 | 默认禁止；仅按正式标准放行 |
| 私属 | 默认隐藏标题、摘要、正文、附件和引用 | 工作台下发标准 | 默认禁止；仅按正式标准放行 |

- 初值按来源、目录白名单和内容类型自动推断；内容分级调整须经工作台标准授权并留痕（操作者、时间、原级别、新级别、理由）。
- 同一矩阵在检索结果、问答引用、附件下载和导出四处统一执行，不出现"检索可见但下载受限"等口径差。
- 历史资料未迁移前默认"私属"；个人敏感内容在未获创始人明确放行前，标题也不返回。
- 每次因分级导致的拒绝（检索、问答引用、附件、导出）写审计：用户、级别、字段、拒绝依据。

## 3. 数据来源与存储边界

### 3.1 来源分层

| 来源 | 首期状态 | 数据接入与可见规则 |
| --- | --- | --- |
| 飞书知识来源 | 按授权范围分期接入 | 通过工作台批准的数据通道和下发权限标准接入 |
| 轻立方个人网盘（飞书） | 资料库：正式文件归档位置，只存方案/文档/合同/文件/logo/小图标 | 灯塔生成文件按规范归档于个人网盘 / 2. 灯塔知识库；不存视频 |
| 历史租户资料（含叁棱镜、事盈） | 待评估历史资料 | 通过批准的数据分流或人工确认清单接入；不直连其他租户应用 |
| 本地存储 | 素材库：大量运行态和临时素材，可能后续删除 | 灯塔运行态和临时缓存；正式成品不落本地 |
| 百度网盘 | 成果库：成品视频或部分视频素材 | 存储成品视频/素材；对外分享链接是共享链接；节点登记链接并按工作台标准控制可见 |

三库定位（明确）：飞书 = 资料库（方案、文档、合同、文件、logo、小图标，不存视频正文）；本地 = 素材库（运行态和临时素材，可能后续删除）；百度网盘 = 成果库（成品视频或部分视频素材，对外分享用共享链接）。

灯塔只扫描其通过批准通道可访问的来源；不以灯塔应用身份直接访问另一飞书租户或其他应用数据库。增量和全量校验机制由批准的数据接口契约定义，接口未确认前不承诺扫描范围和频率。

### 3.2 网盘映射与归档

- 分享材料、扫描日志、解析报告、导出文件和运行记录归档到：`租户轻立方/个人网盘/2. 灯塔知识库/`。个人网盘下不得另建新的顶层目录。
- 灯塔产生的正式内容仍归档在上述灯塔知识库目录；如需把资料分流给其他应用，由工作台按批准通道处理，灯塔不直接写入其他应用归口盘。
- 历史资料扫描后只生成“迁移、删除、保留”清单；灯塔不实现审批流程、不在应用内作审批决定。正式决定由创始人根据清单自行执行，整个体系不引入飞书 OA 环节；灯塔只记录清单状态和执行结果反馈。
- 归档批次以日期记录；目录名称遵循固定编号，不用执行时间改变既定文件夹名。页面生成/导出文件使用事项名称、版本号和日期；管理制度保留上传原名，来源创建/修改时间保留为元数据。
- 迁移建议不按 AI 业务价值自动排序，先按来源映射和时间戳规范归档；价值通过知识节点和检索发现。
- 本地“灯塔扫描/”“行业雷达/”目录只保存运行态和临时缓存，个人网盘是正式归档唯一来源；定期做路径、哈希和批次对账，防止双份漂移。
- 文件删除遵循最新网盘规范：云盘删除同步至灯塔应用回收站并保留 30 天；保留期和同步行为须由获批网盘接口契约验证。灯塔不另建审批流程；任何超出规范的永久删除行为不得自行扩展。

归档映射的完整规则（新增）：

- 跨租户或跨盘迁移后，节点必须保留原租户、原路径和迁移批次作为历史来源字段；正式来源字段更新为目标归档位置。这样权限追溯和检索结果仍能说明内容从哪来。
- 目标盘文件被外部重命名或移动时，扫描任务通过“来源 ID + 源文件 ID + 哈希”重新绑定节点，不新建节点；无法重绑时进入“待人工确认”清单并保留旧路径快照。
- 百度网盘链接节点每月人工巡检；链接失效时只更新节点状态和告警，不自动删除或重新解析。
- 批量归档使用幂等键：同批次重复执行只落一次，重复项进入对账报告；批次级校验包含文件数、哈希抽检和路径规范检查。

网盘映射与命名规范遵循（新增，依据《网盘映射管理与文件命名规范-20261018更新版正式版.md》v3 正式版及《应用搭建结构规范-20261018正式版.md》v1 正式版）：

- 归口唯一：灯塔知识库全部文件归档到轻立方租户“个人网盘 / 2. 灯塔知识库”；不得在该位置外新建顶层目录，不占用中台网盘或企业网盘。
- 命名执行：文件夹带数字前缀（1. 2. 3. …）且编号固定；页面生成/导出文件按“事项名称+版本号+日期”；一律不带公司名称。
- 菜单层级映射：灯塔应用菜单按规范第六节执行——1 级业务大类只展开/折叠，2 级模块是权限分组单位，3 级事项承载流程状态和留痕，4 级科目是最小功能页面；禁止 5 级。
- 模块内部结构：涉及制度/操作模板的模块内，0 号文件夹固定为“0.〔模块名〕制度操作模板历史版本汇总”；生效制度平铺在模块根目录；失效版本自动移入 0 号并改名标注“已失效+日期”。
- 待定稿项：规范中标记“待业务大类梳理后定稿”的 2/3 级子目录条目，灯塔侧不自行定稿；等子菜单结构确认后，按规范“规则更新流程”起草新版草稿（版本号+1、文件名带日期和“草稿”字样、标记“待审核”），不发布、不覆盖旧版，等用户确认后才转正式版。
- 文件命名严格按正式规范第五节：页面生成/导出文件按事项名称、版本号和日期命名；管理制度保留上传原始文件名；所有文件名不带公司名称。文件夹数字前缀和编号固定。
- 规范版本跟踪：当前执行上述 v3/v1 正式版；后续如有新版发布，以最新正式版为唯一依据，旧版仅作历史证据保留。

### 3.3 文件类型与视频三分支（修订，关闭 I1/I3）

- 首期重点解析文档、表格、PPT 和多维表。
- 视频分三类处理：
  1. **飞书云盘视频文件**：飞书不存视频正文，只存 logo、小图标等轻量图片；视频类内容迁移出飞书，飞书侧仅保留链接节点（标题、来源、时间、分类、权限）。迁移操作由创始人按清单自行执行，灯塔记录结果。
  2. **外链短视频（抖音、小红书等）**：纳入"创始人知识分享"流程。可抓取时解析文案、要点和可执行做法入节点正文；抓取受限（反爬、robots、登录墙）时落"仅链接 + 元数据 + 抓取受限"节点并标注原因，不生成摘要，不做模型推测。视频文件本身不落库。
  3. **百度网盘视频**：只登记主/备用可鉴权链接，不解析视频内容，不做自动可用性探测；按月由创始人或指定人员人工巡检链接有效性并更新节点状态。
- 数据库保存视频主链接、备用链接、来源、分类、权限和最近人工巡检结果。
- 员工后续向云盘上传视频时，扫描任务按"上传者身份 + 目录白名单 + 文件类型"组合规则判定并发出预警，不进入正式云盘归档流程。

## 4. 核心业务流程

### 4.1 创始人知识分享与统一会话状态机（修订，关闭 I1）

飞书机器人接收链接或文本，按内容类型分流处理。文档类内容提取正文；视频按 3.3 三分支处理。可解析内容进一步生成摘要、关键词、核心观点、可执行做法、适用场景、风险、关联知识和目标应用建议。

会话状态机：所有分享、扫描、解析、归档、删除任务共用统一状态机，状态为 received → fetched → analyzed → asked → decided → archived/applied → expired，另设 failed 与 dead_letter 终态。每个状态记录进入时间、耗时、输入摘要、失败原因（如有）和幂等键。超时规则：

- fetched 失败（抓取受限、链接失效）→ failed，落"仅链接 + 元数据 + 失败原因"节点，不生成摘要。
- analyzed 后超过 24 小时未获创始人回复 → asked 状态挂起，进入"待确认"列表；累计 7 天未处理 → expired，保留全部中间产物，可重新激活。
- 同一链接重复提交：命中未完结会话时合并到现有会话；命中已归档节点时提示已存在并引用原节点。
- 归档、删除等不可逆操作前执行前置校验（权限、状态、目标路径），失败进入补偿队列（回滚事务或标记 dead_letter 并告警）。

追问规则按内容类型配置：视频和外链分享追问"这个内容你有什么想法？"；长文档和表格在解析完成后追问是否需要应用建议；无正文链接只在归档前确认。

系统生成两类建议：

1. 灯塔自身学习或优化建议。
2. 可能适用的外部应用建议，或创始人指定目标应用后的专项建议。

创始人明确表达归档或应用意图后：

- 只有“归档”才进入正式知识库。
- “应用”由创始人补充具体意见，系统生成结构化方案。
- 本应用内的知识整理动作只在工作台下发权限标准允许时执行；整个体系不引入 OA 审批，迁移/删除清单由创始人自行操作。
- 外部应用只在创始人指定或确认目标后做只读分析；形成需求建议包。跨应用数据通过工作台批准接口分流，不直接写其他应用或其云盘归口。

机器人先返回对话摘要，同时生成结构化飞书云文档，记录来源、分析、创始人想法、建议、决定、目标系统、执行状态和审计信息。

### 4.2 员工贡献箱

员工通过飞书私聊机器人提交工作相关链接、新闻或资料。系统自动解析、去重、分类和质量评估，合格内容进入知识编辑复核队列；复核只负责内容质量与知识沉淀，整个体系不引入 OA 审批。普通闲聊、非工作检索和无关分享不进入知识库。

提醒和算力治理：第一次无关请求轻提示；24 小时内累计 3 次触发正式提醒；继续发生时限制 1 小时；再次触发延长至 24 小时。限制到期自动恢复，创始人可人工解除。所有请求分类、提醒和限制均审计。

### 4.3 云盘扫描与批次控制（修订，关闭批次边界）

扫描任务记录源、目录、文件标识、版本/时间、权限快照、哈希、任务批次和状态。增量任务发现变化后生成解析任务或视频预警；解析失败、权限未知、源不可访问、链接失效和百度网盘不可用均保留原因，不以模型推测替代事实。

扫描结果先进入待解析、待归类、待敏感确认或待迁移清单。迁移、删除或保留的正式决定由创始人根据清单自行执行，整个体系不引入 OA 审批；每批上限 200 个文件，执行前后保存原路径、目标路径、理由、批次和恢复信息，并做批次级前后校验（文件数、哈希抽检、权限快照比对）。灯塔不实现审批表单、节点或审批人规则。

灯塔生成的迁移/删除清单是执行参考，不等同执行授权；创始人确认后自行在对应平台操作，灯塔记录操作结果反馈（成功/失败/跳过），失败项保留原因供下次重试。整个体系不引入 OA 审批环节。

### 4.4 情报监测与发布校验（修订，关闭 I4）

每日新闻是独立内容流，不接收创始人个人知识分享。监测目标管理页面支持人物、公司、品牌、机构/项目和领域的增删改、启停、别名、关键词、监控级别、地域和频率配置；配置操作按工作台下发的权限标准控制，灯塔不自建角色。

现有监测体系需在重做时修复 H12 口径冲突、确认 H13/H14 启用状态、落实"仅人名/重点关注/全量"检索规则。

监测配置模型：目标类型（人物/公司/品牌/机构项目/领域）、别名表、监控级别、关键词、三级地域圈层（镇安本地 / 西安商洛安康 / 全国）、频率、启停状态，全部结构化存储；管理权限按工作台标准执行。

发布前校验闸门：命名红线词典（与光≠宇光、象园≠香橼、镇安真味≠正安真味、艺舞倾城≠艺舞清晨、珍艾字形校验）+ 实体白名单 + 来源必填 + 日期唯一 + 幂等键。目标群包括轻立方·公司总群及与光·全员群，跨租户发送必须经工作台批准的消息路由接口；灯塔不得持有与光租户机器人凭据或直接调用其 API。望向山协作运营群已永久取消。路由接口未获批或不可用时，跨租户推送暂停并告警。校验不通过的条目不得推送，进入待修正队列并告警。

告警覆盖四类：当日无产出、周报缺失、推送失败、发布校验不通过。告警通道与责任动作在实施计划中明确到人和时限。

情报条目是独立节点类型，经来源校验后按权限展示；来源不明或待核实内容默认仅创始人可见。

## 5. 知识节点与检索

### 5.1 初始节点导入与版本身份（新增，关闭 B5/I2）

阶段 0 先冻结实际 nodes_v2.jsonl 文件的路径、行数、SHA-256、生成时间和脚本版本；历史资料中的 69685/69787 只能作为待核对线索，不能直接作为基线。文件缺失时暂停导入，不重扫替代。

- 节点幂等键为“来源 ID + 源文件 ID”；路径只作属性，文件移动或重命名不创建新节点。
- 按新 schema 做字段映射，明确丢弃字段和原因；每批 5000 条断点导入，失败批次进入死信。
- 至少抽样 200 条核对标题、原路径、来源、时间和权限范围；输出逐来源对账报告，禁止静默丢弃。
- 节点内容、摘要和权限快照写入 node_versions；同哈希视为副本候选，同标题不同哈希进入人工合并队列。
- 云盘删除事件按规范同步到应用回收站并保留 30 天；是否可通过获批接口恢复或延迟执行须在阶段 0 验证。导入前保留快照，支持按批次回滚。

首期每个源文件或链接对应一个知识节点。节点包括来源、原路径、主体/领域、标题、摘要、分类、标签、时间、解析状态、敏感级别、权限范围、主/备用链接和审计引用。可抽取的正文和文本结果进入 PostgreSQL 供全文检索；完整解析报告和运行日志按网盘映射归档。

知识节点导航沿用旧应用分类树结构，不重建一套分类体系；展示层按工作台下发的权限标准过滤，创始人全量可见，其他用户只看到权限范围内的分支和节点。扫描任务完成后系统根据知识节点重新梳理分类层级和分支（包括补充、合并和层级调整建议），梳理结果作为清单输出供创始人确认，不自动变更分类树。

首期使用 PostgreSQL 全文检索，并按工作台下发的权限标准执行服务端过滤，替换旧前端静态搜索。精读量和稳定性达到后，在同一 PostgreSQL 增加 pgvector，形成关键词与向量混合检索。所有大模型请求（包括解析、摘要、问答和向量相关模型能力）必须通过与光工作中台总接口；灯塔不得直连模型服务商或保存其 API Key。模型供应商、调用通道、计费与限额由工作台统一管理。LLM Wiki 图谱留到 21:30 精读批量稳定后规划；Ontology 只在图谱运行稳定后评估。

员工问题检索同时返回：

- 基于员工可见内容的带引用简答；
- 可继续筛选的结果列表，包括标题、脱敏摘要、来源和更新时间。

标题、摘要、正文、附件和引用均经过同一套服务端权限过滤，并叠加 2.4 分级矩阵：检索、问答引用、附件下载和导出共用同一份字段级判定，禁止任何旁路。历史资料未迁移前默认私属，不返回标题；个人敏感内容在创始人放行前同样不返回标题。

检索结果与问答引用均执行"先过滤、后生成"：候选集先按角色和分级裁剪，再进入排序和摘要生成；被过滤节点不得进入 LLM 上下文。问答必须引用可追溯来源，无法给出可靠答案时明确说明，不做推测性补全。

## 6. 首页方向

首页暂定“深空观测站”视觉方向：全息知识节点、知识规模和关系作为展示核心；创始人看到采集解析、待确认、应用建议和最近归档；员工看到问题检索和可见知识节点。具体 UI、动效强度和交互细节在开发启动前单独确认。

## 7. 模块与阶段

### 7.1 模块

采集、扫描接入、解析精读、知识节点与检索、归档决策（清单输出，无审批）、情报监测、权限标准接入、应用建议、运营/算力治理、首页展示。

### 7.2 阶段

0. 安全和数据基线：凭据、权限契约、来源清单、审计和迁移/删除保护。交付身份契约、权限矩阵、节点基线和检索验证报告；退出条件是关键未知项有证据或降级；回滚为停止验证，不触碰生产。
1. 个人知识闭环：机器人分享、深度解析、归档确认、全文检索和个人首页。退出条件是端到端成功率和失败原因指标达标；回滚为保留旧分享流程。
2. 主体知识源接入：按工作台批准的数据接口接入来源、解析、索引并执行下发权限标准。退出条件是来源对账和权限抽检达标；回滚为恢复旧扫描任务。
3. 情报监测重做：目标管理、领域口径、每日新闻、周报、推送和告警。退出条件是连续 14 天无缺失且双群推送校验通过；回滚为恢复旧推送。
4. 员工使用：带引用问答、贡献箱、按工作台标准执行字段脱敏、算力治理和客观贡献数据。退出条件是越权抽检为 0 且引用可追溯；回滚为关闭员工问答入口。
5. 历史资料整理：叁棱镜、事盈、本地电脑、轻立方历史盘和百度网盘；只生成清单，创始人按清单自行执行迁移/删除，无 OA 审批环节。退出条件是清单完整且操作结果可追溯；回滚为停止尚未执行的迁移/删除动作。
6. 能力增强：pgvector、精读批量、LLM Wiki 图谱；Ontology 最后评估。退出条件是检索质量和资源成本达标；回滚为关闭增强索引，保留关键词检索。

过渡期规则：阶段 3 验收前，旧 07:30 情报推送和 21:00/21:30 扫描精读任务继续运行；阶段 2 验收后才允许把增量扫描切到新系统；新推送连续 7 天与旧口径一致且无权限事故后，才允许切换推送。

## 8. 安全、审计与失败处理

- 新系统不携带旧应用硬编码凭据；凭据由环境注入或密钥管理，数据库不存明文 Token/Secret。
- 所有管理、扫描触发、配置、机器人和应用方案接口做服务端鉴权；权限标准来自与光工作中台，灯塔不定义角色或权限体系。
- 检索与问答做提示注入防御：外部内容（网页、文档、情报）进入 LLM 前剥离指令样式文本；检索/问答/摘要全程只读数据库，LLM 无写权限；工具调用白名单化并审计。
- 附件下载与导出经 2.4 分级矩阵判定，受限与私属内容禁止导出，全部导出行为留审计。
- 任务使用幂等键、可重试状态、断点和死信状态；定期全量校验发现漏扫、重复和权限漂移。
- 迁移和删除默认不执行；删除确认前提供数量、来源、目标、理由、风险和恢复信息。
- 所有归档、迁移、删除、权限变更、检索拒绝、脱敏、问答引用、机器人提醒和跨应用交付留审计。
- 贡献统计只输出新增数、有效归档数、引用数、重复率、维护及时性等客观数据，并可生成建议等级；不自动写入最终绩效结果。

## 9. 首期验收标准

验收统一量化并分阶段出口（新增，关闭 I2）：

- 阶段 0 出口：灯塔不保存模型服务商凭据；权限/组织/数据接口契约验证报告、来源清单覆盖率 ≥ 95%、审计表可用。
- 阶段 1 出口：创始人分享 → 归档端到端成功率 ≥ 95%，解析失败全部有原因记录，全文检索 P95 < 2 秒。
- 阶段 2 出口：工作台批准来源的全量接入完成率 ≥ 98%，增量任务每日成功率 ≥ 99%，权限过滤一致性抽检 0 差异。
- 阶段 3 出口：每日新闻连续 14 天无缺失，周报失败告警 100% 触达，发布校验拦截率可统计。
- 阶段 4 出口：员工检索 P95 < 3 秒，引用可追溯率 100%，越权检索 0 例（抽检）。
- 全阶段：未达标项进入缺陷清单，不关闭阶段；量化指标由真实监控数据产出，不接受手工汇报。

- 创始人私聊链接可完成深度分析、追问、应用建议和归档/应用确认。
- PostgreSQL 全文检索覆盖已入库节点，结果与角色权限一致。
- 工作台批准的数据来源可运行全量及每日增量接入，任务可重跑且有失败原因。
- 历史来源、个人敏感内容和未迁移资料按规则隐藏或限制。
- 监控目标页面支持实体和领域的增删改停用，并有审计。
- 每日情报与创始人分享分流；推送幂等、来源可追溯、周报失败告警。
- 无关请求按既定阈值提示和限制，且不进入知识库。
- 员工检索返回带引用回答和结果列表；贡献箱进入按工作台权限标准授权的内容复核队列。
- 迁移、删除、应用交付和权限变更均可查询审计记录。

## 9.1 非功能、容量与成本基线（新增，关闭 B3/B4）

以下是阶段 0 的初始目标，真实平台验证后允许下调并记录理由：

| 指标 | 目标 |
|---|---|
| 节点规模 | 支持至少 7 万节点 |
| 增量扫描窗口 | 21:00–23:00 内完成 |
| 解析吞吐 | 500–1000 个文件/日，按来源优先级、目录白名单、时间窗和人工置顶裁剪 |

| 首页 LCP | ≤ 2.5 秒；低端移动端提供静态节点图降级 |
| 数据恢复 | RPO ≤ 15 分钟；RTO ≤ 4 小时 |

容量模型为：节点数 × 平均正文 tokens × 工作台返回的计费口径 × 阶段系数；超出工作台限额时按总接口约定降级为仅返回权限过滤后的结果列表。百度网盘视频容量不计入数据库容量，首期只保存可鉴权链接。

## 11. 备份恢复与安全合规（新增，关闭 I5）

- 数据库：每日全量备份（pg_dump 压缩加密）+ WAL 连续归档，恢复目标 RPO ≤ 15 分钟、RTO ≤ 4 小时。
- 附件与对象存储：按日增量同步到独立存储位置，与数据库备份分离保存。
- 恢复演练：每季度在隔离环境执行一次完整恢复演练，验证备份可用性并记录恢复耗时；演练失败视为高优先级缺陷。
- 备份访问：备份文件加密存储，密钥与数据分离；访问与还原操作全部审计，仅具备工作台下发授权标准的运维身份可执行。
- 凭据管理：轻立方飞书应用及批准数据接口凭据由环境变量或密钥管理服务注入；模型服务商凭据由工作台持有，灯塔不保存。日志、审计、异常上报中自动脱敏（[REDACTED_SECRET]）。
- 敏感数据：个人敏感内容、未迁移历史资料默认私属（见 2.4）；导出、迁移及备份外发按工作台下发授权标准执行，迁移操作由创始人自行执行，灯塔不内建审批。
