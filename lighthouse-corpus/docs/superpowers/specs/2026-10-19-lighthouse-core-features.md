# 灯塔知识库核心功能规范（送审稿）

- **版本**：v1.0（2026-10-19）
- **状态**：待创始人审核确认后发布

## 一、应用定位

灯塔知识库是轻立方租户下的工具层应用，用于沉淀创始人的历史资料、日常分享、行业情报和员工知识贡献。它不参与业务流程审批，不维护第二套组织架构，只消费与光工作中台下发的角色权限标准。

## 二、核心功能需求（八大项）

### 1. 创始人历史资料扫描、分类与重新归档

- 扫描飞书四租户的历史资料，按新 schema 建立节点并分类。
- 迁移策略：飞书四租户 → 迁移到两租户。
- 飞书云盘只保留方案、文档、合同、文件、logo 和小图标；不存视频正文。
- 视频素材迁移出飞书，暂存本地作为素材库；成品作品转百度网盘作为成果库。
- 迁移/删除/保留清单由系统输出，创始人自行执行，灯塔只记录执行结果反馈。

### 2. 三库定位与归档规则

- 飞书 = 资料库：方案、文档、合同、文件、logo、小图标；不存视频正文。
- 本地 = 素材库：运行态和临时素材，后续可按清单清理。
- 百度网盘 = 成果库：成品视频/素材，对外分享使用可鉴权共享链接。
- 灯塔产生的正式归档统一落到：租户轻立方 / 个人网盘 / 2. 灯塔知识库。
- 实际盘 ID、连接器和写入能力待工作台批准后实测。

### 3. 日常新闻情报搜集与推送

- 持续监测指定人物、公司、品牌、机构/项目和领域的公开信息。
- 每日生成新闻摘要并推送到轻立方公司总群和与光全员群。
- 跨租户推送必须经工作台批准的消息路由接口；未获批时暂停并告警。
- 命名红线词典 + 实体白名单 + 来源必填 + 日期唯一 + 幂等键；校验不通过的条目不得推送。

### 4. 日常分享知识点解析归档与应用

- 创始人经飞书机器人提交链接或文本，系统自动解析、去重、分类和质量评估。
- 会话状态机：received → fetched → analyzed → asked → decided → archived/applied。
- 归档后才进入正式知识库；应用建议需创始人补充意见后生成结构化方案。
- 仅当创始人明确表达归档意图时才正式入库；不自动归档。

### 5. 扫描监控与每日增量提醒

- 每日扫描飞书增量文件，自动分类、敏感分级和迁移建议。
- 发现错误归档（视频/素材上传至飞书资料库）时发出预警。
- 批次扫描上限 200 文件/批；执行前后保存原路径、目标路径、理由、批次和恢复信息。
- 失败项保留原因供下次重试；云盘删除同步进应用回收站保留 30 天。

### 6. 员工知识点贡献

- 员工经飞书私聊机器人提交工作相关链接、新闻或资料。
- 系统自动解析、去重、分类、质量评估；合格内容进入复核队列。
- 复核只判断内容质量与知识沉淀，不引入 OA 审批。
- 重复链接自动合并；闲聊/非工作内容不入库。

### 7. 知识节点导航与权限展示

- 沿用旧应用分类树结构，展示层按权限过滤（创始人全量）。
- 扫描后系统重新梳理分类层级和分支，输出清单供创始人确认，不自动变更分类树。
- 敏感分级与字段级处置：公开/内部/受限/私属四级；检索、问答引用、附件下载和导出共用同一套分级判定。
- 私属节点不返回标题；受限节点隐藏正文和附件。

### 8. 预留应用通信接口

- 支持其他应用经工作台批准后调用灯塔接口。
- 接口功能包括：知识节点检索、素材与资料调用。
- 所有外部调用记录审计：调用方、时间、租户、功能、结果。
- 未获批前保持 unknown，不自行假设接口路径或字段。

## 三、与四级菜单规则的关系

- 四级菜单规则（1 级业务大类、2 级模块、3 级事项、4 级科目）是管理、经营、项目类应用的框架要求。
- 灯塔作为工具层知识库，功能需求简单，不套用多层级菜单结构。
- 当前导航为扁平 8 项：首页总览、知识检索、待确认清单、分享流程、贡献箱、扫描批次、情报监测、审计留痕。
- 后续如有需求扩展，按“功能组”而非“业务大类”拆分，保持简洁。

## 四、角色与权限边界

- 组织架构和角色权限由与光工作中台按“组织架构 + 角色”下发。
- 灯塔只消费工作台下发的权限标准，不建立第二套组织或角色体系。
- 员工登录时以飞书身份识别，再由工作台返回组织和角色。
- 双租户（轻立方与与光）员工可安装同一灯塔应用；两边人员统一按工作台角色核验。

## 五、归档路径与网盘

- 正式归档路径：租户轻立方 / 个人网盘 / 2. 灯塔知识库。
- 员工权限：创始人全量查看；公司成员按部门及所授权的应用、项目获得节点查看权限。
- 实际盘 ID、连接器和写入能力待工作台批准后实测；未确认前保持 unknown。
