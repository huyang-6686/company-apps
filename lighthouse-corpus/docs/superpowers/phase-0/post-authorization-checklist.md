# 开放权限获批后首日核验清单（2026-10-18 草稿，待审批流程定稿后修订）

前置：本清单仅在应用已上架开放平台、app_id/secret 由责任方持有且开放权限获批后执行。Codex 不索取、不存储凭据；所有凭据由责任方注入运行环境。

## 1. 凭据与权限确认（责任方操作）

- 责任方确认 app_id/secret 已注入安全存储，不在聊天记录或代码库中出现
- 责任方提供权限范围清单：可访问的接口、租户范围、数据边界、失效时间
- 任何超出清单的访问请求都视为越权，立即停止并记录

## 2. 工作台接口连通性核验

- 用责任方提供的临时令牌调用一次健康检查或最小权限接口，仅记录状态码和响应时间，不记录令牌
- 核对响应中的接口版本、鉴权方式与此前记录的契约字段是否一致
- 契约缺失或字段不一致时，先停在这里请责任方补充，不自行猜测参数

## 3. 节点基线获取

- 由责任方指明 nodes_v2.jsonl 或等效文件的授权访问路径
- 按照本目录 node-baseline.md 中「取得源文件后的执行顺序」六步执行：取证 → 解析校验 → 5000 条批次 → 每批至少 200 条抽样 → 逐来源对账 → 批次回滚预案确认
- 原文件保持只读，不修改、不移动、不删除

## 4. 权限与组织数据核验

- 用测试账号验证：权限同步失败或过期时应用拒绝访问并记录审计拒绝码
- 核对组织架构与飞书通讯录同步结果一致，不出现第二份主数据
- 验证工作台下发的角色在本应用内正确映射，不自建角色

## 5. 归档与审计准备

- 确认归档路径指向「租户轻立方 / 个人网盘 / 2. 灯塔知识库」，不新建顶层目录
- 验证文件命名带数字前缀、不带公司名称，0 号历史目录规则生效
- 确认审计日志追加写入、包含拒绝码和操作者，不可篡改

## 6. 通过标准

以上每项全部通过且无未解释差异，方可宣布阶段 0 数据基线核验完成，进入后续功能设计评审。任何一项失败都停留在当前项，不跳过，不进入下一阶段。
