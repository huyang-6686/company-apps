# 采购需求轻量会签 Demo 设计 Spec（v1.0）

状态：待Harness审阅（用户已于2026-10-21确认全部澄清项并批准草案方向）
项目：business-wangxiangshan（望向山经营中台）
阶段：阶段1 需求澄清与设计 → 审阅通过后进入实施

## 1. 目标与边界

- 交付局域网可访问的最小可操作Demo：采购需求单填报 → 应用内轻量会签 → 逾期提醒/升级 → 状态流转与列表。
- 端口固定3001，start:lan 脚本监听 0.0.0.0:3001，启动前检查占用，被占报错不换端口；不配HTTPS/域名/公网。
- 范围外（显式排除）：正式付款/报销/借款（归飞书OA）、与光同步、飞书真实通知、真实身份登录、生产数据库。
- 模拟边界：登录身份（下拉模拟切换）、通知（站内模拟通知列表，页面显式标注本地模拟）、OA仅占位提示。

## 2. 技术栈

- Next.js（App Router）+ SQLite本地文件（better-sqlite3），重启数据不丢。
- 构建：npm run build；启动：npm run start:lan。

## 3. 需求单字段

填报人（模拟身份）、门店、物品名称/统一物料编号、数量、预计金额、用途、期望到货时间、会签状态、提交时间戳。
金额规则：500元及以下→会签通过后标记员工自采；500元以上→标记对公/借款（OA办理）占位提示。

## 4. 状态机（已确认）

- 草稿（可选）→ 已提交 → 会签中
- 通过：行政或创始人任一人同意即通过（终态）。
- 拒绝：行政拒绝不终态，自动推送创始人复签；创始人拒绝为最终态。拒绝时须填写原因。
- 退回补充：存在该状态，区别于拒绝；行政或创始人（用户本人）均可发起，须填原因。退回后提交人修改后重新提交，单据回到已提交，保留退回历史记录。
- 撤回：会签完成前提交人可撤回；撤回后可修改并重提，保留撤回记录，不物理删除。
- 24小时逾期提醒：每24小时重复提醒一次，提醒对象为当前未处理会签人（行政或创始人，均为会签人时同时提醒）。
- 48小时升级：满48小时未完成时升级通知创始人；升级后行政仍可处理，创始人亦可处理。

## 5. 权限（模拟身份）

- 普通员工：提交本人需求、查看本人单据。
- 行政：查看全部、会签（同意/拒绝/退回补充）。
- 创始人（用户本人）：全量可见、会签、终审拒绝、退回补充。
- 所有身份页面标注本地模拟身份。

## 6. 数据模型（SQLite）

- purchase_requests：id、填报名、门店、物品名/物料编号、数量、预计金额、用途、期望到货时间、状态、提交/更新时间戳。
- request_events：追加式事件表：提交、同意、拒绝、退回补充、撤回、重提、提醒、升级，含操作人、原因、时间。
- notifications：模拟通知列表（接收人、类型、单据、时间、已读）。

## 7. 验收清单

1. npm run build成功；npm run start:lan监听0.0.0.0:3001；端口占用时报错不换端口。
2. 员工提交需求单，字段完整落库。
3. 行政同意→通过；创始人同意→通过；行政拒绝→推送创始人，创始人可同意或最终拒绝。
4. 退回补充→提交人修改重提→回到已提交，历史保留。
5. 撤回→修改→重提路径走通。
6. 模拟时钟验证：24h重复提醒；48h升级通知创始人。
7. 所有模拟身份/通知页面有显式本地模拟标注；无真实飞书/与光调用。
