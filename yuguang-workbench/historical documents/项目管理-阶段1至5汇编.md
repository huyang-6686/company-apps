### 六、教训（`【推断】`）

1. **每次"简化"都靠加字段** → 36 变 37 列，缺的是"删"与"收敛"的机制。
2. **计算列靠 Excel 公式无人校验** → 负值与漏算混进正式报表。
3. **没有状态机就用「垃圾桶」冒充删除** → 三成数据"说不清算不算"。
4. **用命名约定替代主键** → 改名即断链。
5. **流程文档细到 20 事项，系统只提供"填表"不提供"流"**。
6. **统一模型越"统一"越没人用** → 大家宁愿每单自建，因为自建那张才顺手。
7. **至少两轮代际迁移**（V2→V3→V4），V4 又在漂移，正在酝酿第三轮。

### 八、两条关键分界线 `【原话】`

**常规 vs 大项目**：
> 「常规项目记录、大项目独立运用」 → 按**管理深度**分层，不是按金额。
> 「这个需要领导确定」 → 定级是**总经办审批动作**，须留痕。

`【推断】` 架构硬约束：**同一项目主键、两种管理深度、支持原地升格**。若拆成两个独立应用，升格需搬数据 = 第四次迁移。

### 六、推荐：方案 C，以及 C 自己的失败模式

**推荐理由（三条）**

1. **唯一同时满足 H3 和工期**：A 便宜但 H3 靠旋钮；B 能硬治 H3 但没有缓冲；C 把 H3 写在页面里，还留 24 天。

3. **可交接**：页面代码量小、表结构在飞书里肉眼可见、迁移脚本一次性可重跑；对应 R11（开发单点）。

**C 自己的失败模式（必须先承认）**

- 退化路径：批量场景绕回多维表 → 页面成看板 → 成本账无人填 → 毛利率再次缺失。
- 触发条件（可观测）：① 多维表编辑次数 > 页面提交次数；② 录一单成本中位耗时 > 3 分钟；③ 上线第 4 周仍有 >30% 的在办项目无任何成本记录。
- **对策（写进一期范围）**：埋点 1 人日不可砍；月表页必须能导出 Excel（否则财务仍然手工要数）；成本账页必须支持"复制上一单"（同项目重复科目占 70% 以上 `【推断】`）。

**一句话**：**C 不是最优解，是"3 个月 × 1 人"这条边界下唯一不赌运气的解。**

### 4. 成本账结构（C+ 第二部分）

#### 4.1 一张不是两张：为什么必须有成本账

【实测 EQ-06/EQ-13】财务月表 6 项里 **4 项口径不可信、2 项字段不存在**（成本、毛利率不存在）；现有"项目预算表"被当成本账用却长成报价单的样子。C+ 的取舍：**报价留在主表（一行一值），成本进子表（一行一笔）**。

#### 4.2 录入形态（一屏录完）

- 打开成本账页 → 顶部是该项目已录合计、与"签约金额"并排 → 中间是明细列表（只读） → 底部是录入区（表单，非网格）。
- 科目用**预设按钮**（采购/外协/差旅/设备租赁/分包），点一下填进表单，不手打。
- 金额一个框；供应商选已有（可新增）；凭证**直接粘网盘链接**（不读文件、不传文件，一期不碰云盘 API）。
- 外协工时：同一页下方小表，一次录 `外协人 × 天数 × 单价`。
- **「复制上一单」**：复制同项目上一笔（或上一个项目的同科目行），科目出现率高的场景占大头【推断，阶段 3 已载】。
- 目标：**录一笔成本 ≤90 秒**【推断，阶段 3 §3 C② 已载，是 A/B/C 共同的生死线】。

#### 4.3 成本合计（H9 口径，写死在字段名上）

```
成本（含外协工时，不含自有工资）
  = Σ 成本明细.含税金额（或不含税，见 4.5）
  + Σ 外协工时.金额
自有员工工资：不进来（不进、不算、不展示）
```

#### 4.4 H7 双向可跳（一期只做到"能跳"，不做深绑定）

| 方向 | 一期怎么做 | 是否触犯硬边界 | 分级 |
|---|---|---|---|
| 成本账 → 网盘 | 明细行「凭证链接」点开直达 `2.合同回款 / 供应商结算 / <项目>` | 否（只存链接） | 【原话 H7】 |
| 网盘 → 成本账 | 网盘目录结构**不改**；系统提供"唯一码直达"（列表搜索框输唯一码 → 直开该项目成本账页），该直达链接回填到项目的飞书云文档说明里 | 否（不建目录、不写文件） | 【推断】 |
| 自动反链（系统往网盘写文件） | **二期**，属"网盘深绑定" | **是，一期禁止** | 【原话 N6 / 第五节硬边界】 |

#### 4.5 价税分离口径

- 明细**以含税金额录入**（人手里的发票是含税价），系统算不含税与税额；税率固定 6%。
- 月表第 5 项「成本」默认报**含税**，另给一列不含税（导出 Excel 里并列，不替换）【推断 A6-8】。

### 6. 状态机（四态 + 作废原因）

#### 6.1 四态与允许的跃迁

```
          ┌────────────── 已废（终态，不可复活）
          │  作废原因必填/取字典/不可物理删除
   在办 ──┼──> 已签 ──> 已完（终态）
   (open) │    (signed)   (done)
          └────── 不可作废

禁止：已签 → 已废 ｜ 已完 → 任何 ｜ 已废 → 任何 ｜ 任何 → 在办（回退）
```

| 跃迁 | 触发 | 保存即校验（硬校验） | 软提示（不阻断） | 分级 |
|---|---|---|---|---|
| 新建 → 在办 | 点「新建」并保存 | 立项名称、业务类型、资质主体、项目主管、立项日期、唯一码（系统生成）必填 | — | 【原话 EQ-01b/A1-1 + 推断】 |
| 在办 → 已签 | 表单改状态 | 签约金额 > 0、签约日期、资质主体、业务类型 | 报价金额为空；测算未补 | 【推断】 |
| 已签 → 已完 | 表单改状态 | 交付日期 | **成本一条未录**（提示"毛利率将无法计算"，但**不阻断**——阻断会把人推回多维表） | 【推断，理由见 11.3】 |
| 在办 → 已废 | **只此一条作废路径** | 作废原因（字典）、作废时间、作废人；**不可物理删除** | — | 【原话 C5「作废只能从在办跃迁」+ C5b「已废保留」】 |
| 已签 → 已废 | **不允许** | — | — | 【原话 C5】一期无出口 → 登记第 12 节 Q1 |
| 已完 / 已废 → 其它 | **不允许** | — | — | 【推断】更正走"冲销/更正"，一期不实现（第 12 节 Q2） |

#### 6.2 作废原因（字典，一期 6–8 项）

报价未中 / 客户取消 / 预算砍 / 资质不符 / 内部放弃 / 重复立项 / 其他【推断，阶段 2 已建议，阶段 5 定稿】

- 历史 363 条：迁入即「已废」，原因填 **「历史废单·原因未记录」** —— 此项为我方建议，**未获负责人确认**，登记第 12 节 Q3【推断/待确认】。

#### 6.3 状态与报表的关系

- 已废：不进 1/2/3/5/6/7 项的分子，只进第 8 项分母与全量废单率【原话 C5b】。
- 已完：算业绩；若后来发现金额错，不允许改回在办，走更正（二期）【推断】。

### 7. 批量操作（C+ 的定案理由，不可砍）

【原话：负责人否决 C 原形的唯一事由 = 批量场景绕回多维表 → 薄层退化成看板 → 成本账无人填；「按 C+ 定」= 补批量。】

| # | 能力 | 行为 | 关键约束 |
|---|---|---|---|
| B1 | **批量改状态** | 勾选 N 条 → 只能在允许的跃迁里选（在办→已签、已签→已完） | 已废/已完 不出现在候选；每条校验同 6.1 |

**批量操作的三条实现纪律**【推断】：
1. 预校验与写入是**两次独立调用**，不许边校验边写。
2. 写入按 V2 实测的批上限**分批**（批次大小待 V2 定，第 10.1 节）。

### 2.8 不变量（Invariants，越线即 bug）

1. 一条项目 = 一个**唯一码**，且只有一个数据源（主表）。
2. 只有页面②能产生新记录；「新建」之外无任何建行路径（H3）。
3. 已废不可物理删；已废不可复活。
4. 成本只在子表，主表的成本值永远是计算值，**不允许手填**（H5/H9）。
5. 毛利率字段名、成本字段名**永远带口径标记**，任何界面/导出/API 都不得简写（H8/H9）。
6. 未回款、成本、毛利率、滞后天数、停滞天数**全部计算得到**，无手填入口（P8 脏值对策）。

### 3.7 计算定义（伪公式，页面与导出口径一致）

```
距上次更新N天   = DATEDIFF(今天, 最后更新时间)
当前节点卡N天   = DATEDIFF(今天, 状态变更时间)
未回款金额      = 签约金额 - 回款金额            // 可负，负值标红
成本            = SUM(成本明细.含税金额) + SUM(外协工时.金额)
签约毛利率      = IF(成本明细条数+外协工时节数 == 0, "成本未录",
                    IF(签约金额 > 0, (签约金额 - 成本) / 签约金额, "—"))
不含税金额      = 含税金额 / (1 + 税率)
税额            = 含税金额 - 不含税金额
```

2. 计算字段不得被任何人手工覆盖；页面不渲染其输入框。
3. 字段改名必须同步：页面、导出列名、本文档、迁移脚本映射表。

## 第 5 章 状态机

### 5.1 状态

| 状态 | 含义 | 终态 |
|---|---|---|
| 在办 | 已立项，未签约 | 否 |
| 已签 | 已签约，未交付完 | 否 |
| 已完 | 已交付/验收完成 | **是** |
| 已废 | 项目黄了（死单/未成交/中途终止） | **是（不可复活）** |

### 5.2 跃迁矩阵

| 从 → 到 | 允许 | 硬校验 | 软提示（不阻断） | 错误码 |
|---|---|---|---|---|
| 新建 → 在办 | ✅ | R-01/02/03/09/10 | 无测算 | — |
| 在办 → 已签 | ✅ | R-07（签约金额>0、签约日期） | 报价为空 / 测算未补 | E-ST-01 |
| 已签 → 已完 | ✅ | 交付日期必填 | **成本一条未录**（提示"毛利率将无法计算"） | E-ST-02 |
| 在办 → 已废 | ✅ | R-05（原因/时间/人） | — | E-ST-03 |
| 已签 → 已废 | ❌ | — | 「已签项目不能直接作废」→ 见 Q1 | E-ST-04 |
| 已完 → 任意 | ❌ | — | 更正走冲销（二期，Q2） | E-ST-05 |
| 已废 → 任意 | ❌ | — | 要复活 = 新建记录并关联原唯一码 | E-ST-06 |
| 任意 → 在办（回退） | ❌ | — | 一期不提供 | E-ST-07 |

> **为什么"未录成本"只提示不阻断**【推断】：硬阻断会让人在系统外先记账、再挑时间补录，直接催生 F2（成本账无人填）。宁可让数据显性缺失（月表显示"成本未录"），也不能让人绕开系统。

### 5.3 作废原因（字典，一期 6–8 项）

报价未中 / 客户取消 / 预算砍 / 资质不符 / 内部放弃 / 重复立项 / 其他【推断，阶段 5 定稿，见 12.3】

- 新废单：原因必填、取自字典、**不允许"未记录"**。
- 历史 363 条：原因填「历史废单·原因未记录」（我方建议，**未获负责人确认** → Q3）。

### 5.4 联动

| 对象 | 联动规则 |
|---|---|
| 滞后列 | 状态变更即重置"卡 N 天" |
| 月表 | 已废不进业绩分子；进废单率分母 |
| 测算 | 状态=在办 且 测算状态=未补 且 超过截止日 → 测算状态自动置"超期"（每日计算，不写库） |
| 批量 | 批量改状态复用 5.2 全部规则 |

## 第 6 章 成本账与月表口径

### 6.1 成本定义（H5 + H9）

```
成本（含外协工时，不含自有工资）
  = Σ 成本明细.含税金额（科目：采购/外协/差旅/设备租赁/分包）
  + Σ 外协工时.金额（外协人 × 天数 × 单价）
不进成本：自有员工工资、社保、公积金、内部人力分摊
```

**重建而非平移**（H5）：早期 Excel 模型的科目树与 `SUBTOTAL(9,D2:D14)` 漏算**一律不搬**，科目按上表 5 类重建，可增项但需版本记录。

### 6.2 录入规格

| 项 | 规格 |
|---|---|
| 录入单位 | 一行一笔支出；外协工时为独立小表 |
| 含税/不含税 | 录入金额为**含税**（人手里的发票口径）；系统算不含税与税额 |
| 税率 | 固定 6%，字段保留（H10）；13% 分支不实现 |
| 归属月 | 按「发生日期」/「发生月份」 |
| 凭证 | 粘链接，不传文件（一期不做云盘 API） |
| 一屏 | 全部输入在同一屏内完成，**不需要滚动到第二个页面** |
| 复制上一单 | 复制同项目/同科目上一笔的科目、供应商、交付项、税率；金额与日期清空 |

### 6.3 价税分离（A6-8）

- 明细同时存：含税金额（录入）、不含税金额（算）、税额（算）、税率（固定）。
- 月表「成本」默认报**含税**，导出 Excel 时并列不含税与税额（不替换）。

### 6.4 供应商结算 ↔ 成本账（H7）

| 方向 | 一期实现 | 二期 |
|---|---|---|
| 成本行 → 网盘 | 点「凭证」直达 `2.合同回款/供应商结算/…` | — |
| 网盘 → 成本账 | 项目目录结构不变；系统提供「唯一码直达」（列表搜索唯一码 → 打开该项目成本账页），该链接回填到项目飞书云文档说明 | 自动反链（写文件）属深绑定，二期 |
| 自动建目录/改名 | **一期完全不做**（H6） | 二期 |

### 6.5 月表 8 指标（口径写死）

| # | 指标 | 公式 | 归月 | 含已废 | 分母0/缺失 |
|---|---|---|---|---|---|
| 1 | 报价金额 | Σ 报价金额 | 立项日期月 | 否 | 空不计；显示"报价未填 N 条" |
| 2 | 签约金额 | Σ 签约金额 | 签约日期月 | 否 | 显示"签约未填 N 条"（2026 缺 61.3%【实测】） |
| 3 | 回款金额 | Σ 回款金额 | 回款日期月 | 否 | 显示缺失条数 |
| 4 | 未回款金额 | Σ(签约 − 回款)，**累计至月末** | 时点 | 否 | 标注"截至 YYYY-MM-DD" |
| 5 | 成本（含外协工时，不含自有工资） | Σ 明细 + Σ 工时 | 发生日期/月 | 否 | 显示"零成本项目 N 个" |
| 6 | 签约毛利率 | (当月签约项目签约 − 其已录成本) / 当月签约金额 | 跟随第 2 项 | 否 | **成本未录 → 「成本未录」**；分母0 → 「—」 |
| 7 | 回款率 | 当月回款 / 当月签约 | 当月流量 | 否 | 分母0 → 「—」 |
| 8 | 废单率 | 当月新增已废 / 当月新增立项 | 当月 | 分母含 | 分母0 → 「—」；另单列全量 **29.3%**（363/1241【实测】） |

### 6.6 四条报表纪律

1. 默认只算 **878 有效**；363 已废不隐去、不并入业绩。
2. 字段名永远带口径：`成本（含外协工时，不含自有工资）`、`签约毛利率（分母 = 签约金额）`。
3. **成本未录 ≠ 0**：显示「成本未录」，绝不按 0 算毛利率（否则虚高 100%，管理层被骗）。
4. 月表**必须能导 Excel**，否则财务继续手工要数，成功标准 ①② 落空。

### 6.7 导出 Excel 列定义

`唯一码 | 立项名称 | 年份 | 业务类型 | 资质主体 | 项目主管 | 项目状态 | 立项日期 | 签约日期 | 报价金额(含税) | 签约金额(含税) | 回款金额(含税) | 未回款金额(含税) | 成本（含外协工时，不含自有工资）(含税) | 成本(不含税) | 税额 | 签约毛利率（分母 = 签约金额） | 距上次更新N天 | 当前节点卡N天`

## 第 8 章 失败模式与回退

> 每条都写：**可观测触发条件 → 怎么测 → 处置 → 退出/回退路径**。

### 8.1 F1｜V2 验不过：API 慢 → 页面卡 → 人不用 → 退化看板（R13）

| 项 | 内容 |
|---|---|
| 触发条件 | 读 200 条 P95 > **2.0 s**；批量写 20 条 > **10 s**；单条写 P95 > **1.5 s**。任一命中即判"不成立"【推断，待 V2 校准】 |
| 怎么测 | `Invoke-RestMethod` 最小脚本（8.9），不建工程、不动生产表 |
| 处置 | **立即退 B**（52–54 人日 / 缓冲 6–8 天），按 8.10 差异清单改本文档 |
| 回退路径 | 退 B 时**本文档 3/5/6 章可直接复用**（数据模型、状态机、成本账与月表口径不变），只换载体 |

### 8.2 F2｜成本账无人填（成功标准 ③ 的根）

| 项 | 内容 |
|---|---|

### 9.3 UAT 验收清单（上线判据）

**页面①列表（5 条）**
1. 任一字段在列表上不可编辑（点/双击/粘贴均无效）。
2. 默认不显示已废；勾选"含已废"后显示 1,241 条量级。
3. 「距上次更新」「卡 N 天」与实际日期差一致（抽 3 条手算）。
4. 唯一码搜索精确命中；名称模糊命中。
5. 勾选 3 条后批量条出现，取消勾选后消失。

**页面②表单（6 条）**
1. 不点「新建」不产生记录（刷新页面记录数不变）。
2. 唯一码只读；清空必填项保存 → 报错且不写入。
3. 在办→已签（无签约金额）→ 被拒并提示 R-07。
4. 已签→已废 → 被拒并提示 E-ST-04。
5. 在办→已废（不填原因）→ 被拒；填原因 → 成功且不可删。
6. 两人同时编辑，后保存者收到"已被他人修改"提示。

**页面③成本账（6 条）**
1. 一笔成本保存后，页头"已录成本"与毛利率立刻更新。
2. 科目只能按钮选，无自由文本。
3. 税率只显示 6%，无修改入口。
4. 「复制上一单」带出科目/供应商/交付项，金额与日期为空。
5. 10 笔抽测中位耗时 ≤ 90 s。
6. 界面上不存在"删除"按钮。

**页面④月表（6 条）**
1. 8 项指标齐全，成本与毛利率的列名带口径。
2. 已废项目不进签约/报价/回款/成本。
3. 全年 1,241 条时，废单率显示 29.3% 量级。
4. 成本全未录时，毛利率显示「成本未录」而非 100%。
5. 导出 Excel 列名与 6.7 完全一致。
6. 财务角色看不到任何保存按钮。

**批量（6 条）**
1. 批量改 20 条（全部合法）→ 成功，回执写"已写入 20 条"。
2. 批量改 20 条（其中 1 条不合法）→ **0 条写入** + 逐条错误清单。
3. 批量打废含 1 条已签 → 整批拒绝并指出该条。
4. 批量指派后，列表显示新主管。
5. 模拟写入阶段失败（如限流）→ 回执显示"已写入 X / 失败 Y" + 重试按钮。
6. 所有批量结果在「使用日志」E09 里可查。

**迁移（4 条）**：7.6 全绿 + 20 条抽检 + 任一年列表可用 + 幂等重跑不产生重复行。

### EQ-01b · 出错的具体形态（已答 18:21:19）

**问**：上一次你发现某条记录填错了，是什么情形——错在哪个字段，你怎么发现的，后来怎么补的？

- 列表必须**只读**，编辑走"打开某一条"的表单；

**问**：这些项目预算表，是给甲方看的报价单，还是内部算成本的账？

**由此产生的矛盾（这是 P1 的真正结论）**：
- 它**本该是成本账**，却按"交付内容 × 单价 × 数量"的方式编排（150期短视频 × 200、162场直播 × 800）。

| 表 | 面向 | 结构 | 数据来源 |
|---|---|---|---|
| **报价**（对甲方） | 销售/商务 | 按交付内容 × 单价 × 数量 → 报价总额 | 已存在于订单表「报价金额」字段 |

> 报价 − 成本 = 毛利。**目前只有报价，没有成本账 → 所以才永远算不出毛利率。**

### C6 · 毛利率的分母（已答 20:20:00）

**问**：毛利率的分母用签约金额，还是回款金额？

**原话**：
> 签约金额

**提取事实**：
1. **毛利率 = （签约金额 − 项目成本）/ 签约金额**。定案。
2. 这意味着系统里"确认收入"的基准是**签约**，不是回款 → 于是**回款风险必须单独一个指标**（回款率 / 未回款额），否则"签了收不回"会被毛利率掩盖。
3. 与财务月表 6 项的关系：签约(分母) + 成本(分子) + 毛利率(派生) 是一条链；回款/未回款是**另一条链**（现金流）；两条不能混算。
4. 因此月表至少要有 **8 项**而非 6 项：报价、签约、回款、未回款、成本、毛利率、**回款率**、**废单率**。

**由此产生的硬要求**：毛利率必须带**签约口径标记**（"签约毛利率"），不得与"回款毛利率"混用；未来若要加回款口径，作为第二列并列，不替换。

**提取事实**：
1. **成本 = 外部支出 + 外协/兼职工时**；**自有员工工资不进项目成本**。定案。
2. 因此"外协人员"必须成为系统里的一个实体（可挂在供应商结算下），并有**工时记录**——否则"部分含"落不了地。
3. 报表上须写死口径：**「成本（含外协工时，不含自有工资）」**，避免半年后有人拿它跟含全人工的毛利比。
4. 直接后果：毛利率会**略高于**全成本口径，管理层需知道这一点；这也是为什么阶段 1 说"没人再问赚没赚"最难——数字真了，口径还得说清。

**C6 系列结题。** 一句话：**分母用签约，分子用"外部支出+外协工时"，自有工资不进账，口径必须写在字段名上。**

**C9 结论一句话**：**一期不做权限，靠界面不给入口；但"没权限"这个风险会被带进上线后的运行期，且没有任何审计。**

### 二、完整科目树与计算逻辑（实测公式）

```
销售收入
└─ 收入额                              按销售合同或有效依据填写

销售成本
├─ 采购成本
│   ├─ 设备采购          项目交付必须的设备采购成本
│   ├─ 设备租赁          项目交付必须的设备租赁成本
│   ├─ 实物物料采购      耗材、零配件等配套物料
│   ├─ 数字物料采购      平台、会员、2D素材、3D资产
│   └─ 外协成本          外部协作人员或外包直接成本
├─ 营销成本              广告费、商务费、居间费、招待费
└─ 其他成本

销售费用
├─ 差旅住宿费            （参照员工手册对应标准）
├─ 差旅交通费            市内交通 + 差旅交通（车票/机票）
├─ 车辆使用费            私车公用：油费、停车费、过路费
├─ 快递物流费
└─ 其他费用

财务费用
├─ 增值税                销售类：(收入-采购成本)*13%　｜　服务类：收入*6%
└─ 资金成本              (销售成本+销售费用)*7%（年化）/365*回款周期
                          回款周期基准：联通渠道 180 天　｜　市场渠道 90 天

销售毛利 = 收入 - 销售成本 - 销售费用 - 财务费用
```

### 四、四个关键发现

#### F1 它是"立项前置决策器"，不是事后核算
模型说明写着「**测算后净利>0 再考虑承接项目**」→ 成本测算发生在**立项之前**，用来决定接不接这单。
但订单表里「项目成本测算模型」是挂在**已立项**记录上的一个文件链接，2026 年 100% 为空。
→ **流程顺序错了**：该前置的环节被放到了立项之后，且没有强制。

#### F2 审批粒度是"支出明细行"，不是项目
`支出明细` 每行有独立 `审批单号`。这说明 OA 审批同步要支持 **按笔支出**回填审批单号，而不是只在项目层面同步一次。
→ 这对"OA 审批同步"的接口深度提出了明确要求：需要**单据级**关联。

#### F3 项目类型只有 2 类，订单表已有 10 类 —— 冲突
成本模型的 `项目类型` 只有 **服务类 / 销售类**（决定增值税算法 6% 还是 13%）。
订单表的 `业务类型`：2021–2025 是 `服务 / 销售`（2 类，对得上），但 **2026 变成 10 类**：综合服务、培训、商管、活动、视频、直播间、图文运营、直播、商贸、aigc。
→ 两个分类体系**已经脱钩**。必须先建 `10 类 → 2 类（税务口径）` 的映射，否则成本测算无法自动取数。

#### F4 `支出明细` 的合计公式漏算（真实缺陷）
```
R25: 合计（验证）  D列 =SUBTOTAL(9,D2:D14)   E列 =SUBTOTAL(9,E2:E14)
```
但明细区实际到 **第 24 行**（23 个明细行）。公式只覆盖 D2:D14 共 13 行 →
**第 15–24 行的支出不会进入合计**，而 `成本测算模板` 又是按分项名 SUMIFS 直接从明细取数、不经过这个合计，
所以主表可能对、校验行却错 —— 一个"看着像校验、其实校验不了"的公式。
> 这正是"靠 Excel 公式承载财务逻辑"的典型风险。

## B2 · 15 份项目预算变体比对

> 来源文件：`.project-board/recon-02-budget-variants.md`（62 行）｜本段为原文，仅标题降一级

## RECON-02 · "更新版"的真实形态

> 触发：负责人说成本测算模型"更新"。我在 E 盘全盘检索 `*成本* *预算* *测算*` 的 xlsx，按修改时间倒序，共命中 20 余个文件。
> 结论：**不存在一版统一的新模型。"更新"的真实形态是——每个项目各自长出一张单表预算。**

---

### 一、没有新版，只有十几个变体

| 项目 | 变体文件 | 份数 |
|---|---|---|
| 镇安真味品牌推广 | `...预算.xlsx`、`_单表版`、`_单表版1/2/3/4`、`_6`、`_7` | 8 |
| 留坝直播电商人才培训 | `...项目预算v4 (1)`、`v5 (1) - 副本`、`留坝AI培训项目预算` | 3 |
| 渭南（渭滨区）农业培训 | `渭南培训项目预算v4(2)`、`报价方案 v2`、`v3`、`v2.` | 4 |
| 统一模型 | `项目成本测算模型（25-xxxxx） .xlsx`（31,484 B / 31,685 B 两个副本） | 2 |

> 版本管理全靠文件名：`_6`、`_7`、`单表版3`、`v2.`、`v4(2)`、`v5 (1) - 副本`。
> 这与订单表"字典逐年漂移"是**同一种病**：无版本控制，靠人记。

---

### 二、三个变体的结构对比（实测）

| | 早期统一模型 | 镇安真味 `_7` | 留坝 AI 培训 |
|---|---|---|---|
| 工作表数 | 3（明细 / 测算 / 参考值） | **1**（预算明细总表） | **1**（sheet） |
| 列结构 | 类别 / 分项 / 说明 / 预计 / 实际 / 差异 / 差异率 / 差异原因 / 凭证 | 序号 / 费用大类 / 服务内容 / **单位 / 单价 / 数量** / 金额 / 说明 | 名称 / 板块 / 服务内容 / **单价 / 数量 / 单位** / 总价 / 备注 |
| 行数 | 25 行科目树 | 24 行报价明细 | 31 行报价明细 |
| 合计 | `SUBTOTAL(9,D2:D14)`（**漏算 R15–R24**） | **848,200 硬值，无公式** | `=SUM(G3:G33)` ✔ |
| 是否含成本科目 | ✔ 含（采购/费用/财务费用） | ✘ 无 | ✘ 无 |
| 是否含税/毛利 | ✔ 含（增值税、毛利、毛利率、净利） | ✘ 无 | ✘ 无 |
| 分级维度 | 成本科目 | **服务品类**（统筹/短视频/直播/活动/矩阵/平台） | **培训板块**（摸底/基础/进阶/孵化/配套） |

**列顺序都不统一**：镇安真味是 `单位→单价→数量`，留坝是 `单价→数量→单位`。
→ 同一个团队、同一个季度做的两张表，**列序相反**。将来导入系统时字段映射会直接错位。

---

### 三、三个新问题

#### P1 报价与成本被揉进同一张表
留坝表里 `讲师费（含餐费、交通）-讲师1人 2500/天`、`学员午餐餐费 30/人`、`学员住宿 200/间` —— 这些**是成本项**，但被当作"对客户的服务内容"报价出去，成本没有单独留痕。
结果：**这张表既是报价单，又是成本账，但两者都不是**。无法回答"这单赚了多少"。

#### P2 总预算硬值，不可校验
镇安真味 `项目总预算 848,200` 是手写常数，不是 `=SUM(...)`。
→ 明细改了总数不会变。这正是"看起来有总数、其实是假的"的同类缺陷（与早期模型 F4 同源）。

#### P3 分级维度不一致
早期模型按**成本科目**分（设备采购/差旅…），项目预算按**交付内容**分（短视频/直播/活动…）。
→ 两者是**两个正交维度**，不是同一套分类的迭代。系统必须同时支持：
- 对甲方：按交付内容报价（`150期短视频`、`162场直播`）
- 对内：按成本科目核算（`外协`、`差旅`、`设备租赁`）
并把一个交付项**拆解**到多个成本科目。

---

### 四、结论

> 所谓"更新"，不是把旧模型改对了，而是**绕开统一模型、每单自建一张表**。
> 这解释了订单表里「项目成本测算模型」列 2026 年 100% 为空——**没人再往模型里填了，大家在自己项目文件夹里另起炉灶。**
> 所以系统要做的不是"实现那个 Excel"，而是**把"一张报价单 + 一张成本账"的结构固化下来，并让它们对上**。
