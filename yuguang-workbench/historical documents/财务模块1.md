## 1. 项目背景

### 1.1 主体与范围

- 主体：镇安文投公司下属数字技术团队，为**独立分公司/子公司**，持有独立统一社会信用代码与税号。
- 纳税人身份：**小规模纳税人**，增值税独立申报；企业所得税**单独核算、独立汇算**。
- 团队规模：15–50 人；月报销/付款单据 150–400 笔；在跑项目 15–40 个。
- 财务力量：**1 人**（财务负责人）承担审核、复核、记账、报税全流程；团队负责人终审、总经理终审。

### 1.2 现有工具格局

| 工具 | 承担 | 与本项目关系 |
|---|---|---|
| 金蝶 AI 星辰版 | 凭证、科目余额、总账、报表 | **法定账簿归属地**，中台不取代 |
| 电子税务局 | 开票、增值税及附加、所得税预缴与汇算 | 中台只做台账与提醒 |
| 自然人电子税务局 | 个税代扣代缴申报 | 同上 |
| 银行 U 盾网银 | 制单、复核、付款、代发、对账 | 付款动作在 U 盾，中台不管钱 |
| 飞书 | 组织架构、审批、网盘、通知 | **只对接，不重造** |
| Excel 台账 | 资金、费用、往来等业务台账 | 本项目要替代的正是这一层 |

### 1.3 现状痛点

1. 台账散在 Excel，与金蝶两套口径，靠人工核对，月结耗时长。
2. 费用报销靠 OA 单 + 手工登记，三单（合同/验收/发票）匹配靠眼看。
3. 预算只在 Excel 存在，报销时无法实时知道余额，超预算只能事后发现。
4. 项目成本归集靠人脑，15–40 个项目的毛利算不准、算不勤。
5. 税务申报靠日历提醒与记忆，申报台账、完税凭证、风险事项无系统承载。
6. 无留痕纪律：Excel 可直接改、可直接删，审计时说不清。

### 1.4 建设目标与非目标

**目标**
- 用一套自建 Web 系统承载 15 个子域的业务台账、流程、提醒与留痕。
- 报销 → 三单匹配 → 付款 → 资金台账全程线上，月结不再手工搬数。
- 项目成本与毛利随时可算；预算执行实时可见并硬控。
- 税务申报有日历、有台账、有风险库。
- 所有变更可追溯，禁止物理删除。

**非目标（明确不做）**
- 不做凭证引擎、不做总账、不做法定报表编制（归金蝶）。
- 不做资金支付（付款仍在 U 盾网银完成）。
- 不做电子税务局直连申报（政策与安全风险过高）。
- 不做代收代付结算（业务上不存在）。
- 不做 AI 自动记账（AI 结果必须人工确认）。

## 4. 技术方案

### 4.1 架构总览

```
                    ┌──────────────────────────────┐
                    │           飞书开放平台         │
                    │  登录 / 组织 / 审批 / 网盘 / 机器人 │
                    └───────────────┬──────────────┘
                                    │ HTTPS + 事件回调
┌───────────────────────────────────▼───────────────────────────────────┐
│                     财务管理中台（单体 Next.js 15）                      │
│                                                                        │
│  接入层   AuthModule(扫码)  CallbackModule(事件)  ApiModule(REST /api/v1) │
│  ───────────────────────────────────────────────────────────────────── │
│  子域层   treasury │ expense │ payable │ receivable │ contract          │
│           budget   │ project │ revenue │ invoice    │ tax               │
│           ledger   │ archive │ control │ collab     │ digital           │
│  ──────────────────────────────────────────────  ───────────────────── │
│  能力层   RuleEngine(校验) │ BudgetGuard │ MatchEngine │ PermissionGuard │
│           AuditLog │ Reminder │ AiProvider │ Exporter │ DriveSync       │
│  ───────────────────────────────────────────────────────────────────── │
│  数据层   Prisma ORM  →  PostgreSQL 16                                   │
│           MinIO（附件原件）  →  定时同步飞书网盘                          │
└────────────────────────────────────────────────────────────────────────┘
                                    │
                        人工：金蝶（凭证/总账/报表）
                        人工：电子税务局（申报）
                        人工：U 盾网银（付款）
```

**架构原则**
1. **子域隔离**：子域只能通过对方 `service` 暴露的方法读写，禁止跨子域直接查表。
2. **单一真相源**：每类数据只有一个归属子域；其他子域只持有引用。
3. **默认拒绝**：所有路由与 Server Action 必须显式声明权限，未声明即拒绝。
4. **写前三件事**：权限判定 → 业务规则校验 → 留痕快照，缺一不写库。

### 4.2 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 前端/后端 | Next.js 15（App Router）+ React 19 + TypeScript 5 | 一种语言通吃，单人维护成本最低 |
| ORM | Prisma 6 | 类型安全、迁移可读、schema 即文档 |
| 数据库 | PostgreSQL 16 | 事务、窗口函数、物化视图、JSONB |
| 对象存储 | MinIO（自建） | 与服务器同机，零流量成本 |
| 反向代理 | Nginx | TLS、限流、静态缓存 |
| 容器 | Docker Compose | 单机可运维 |
| 定时任务 | 进程内调度（node-cron）+ 数据库锁 | 单机足够，避免引入额外组件 |
| 导出 | ExcelJS（服务端） | 报表导出 |
| 飞书 | `@larksuiteoapi/node-sdk` | 官方 SDK |

### 4.3 部署拓扑（单机）

```
云服务器 4C8G / 100G SSD
├── nginx        :443  TLS 终止，反代 app
├── app          :3000 Next.js（production build）
├── postgres     :5432 数据卷持久化
├── minio        :9000 对象卷持久化
└── cron(容器内) 每日 08:30 提醒 / 02:00 网盘同步 / 03:00 备份
```

备份：`pg_dump` 每日 03:00 → 本地保留 30 天 → 上传异地对象存储；MinIO 卷同步备份；备份失败与网盘同步失败均触发飞书告警。

### 4.4 无 Git 的版本管理（负责人已确认不装 Git）

| 原 Git 规则 | 替代做法 |
|---|---|
| `task/<编号>-<短名称>` 分支 | `snapshots/YYYYMMDD-HHmm-<批次名>/` 快照目录 |
| 提交前列待提交文件 | `.project-board/changes.md` 每批列清单，负责人确认后才打快照 |
| 不提交历史源码/压缩包/密钥/.env/真实数据 | 打包脚本内置排除清单 |
| 不 `git add .` | 只收录清单内文件 |

**已知损失**：无法并行开发、无法回滚到任意历史点、无法 diff 分支。已在阶段 4 由负责人确认接受。

## 5. 模块设计（15 子域）

> 每个子域固定四要素：**职责 / 核心表 / 关键流程 / 边界（不做什么）**

### 5.1 treasury 资金管理
- **职责**：银行账户信息库、U 盾保管记录、收支流水、资金日报、多账户余额、银企对账记录与未达账项。
- **核心表**：`bank_account`、`fund_flow`、`bank_reconciliation`、`reconciliation_item`
- **关键流程**：收款确认 → 登记流水；付款完成（U 盾回单）→ 登记流水 → 关联付款单；月末对账 → 填余额调节表 → 未达账项跟踪。
- **边界**：**不发起付款**，不持有 U 盾凭据，不直连银行。

### 5.2 expense 费用管理
- **职责**：报销单全生命周期、票据合规校验、报销标准校验、预算占用、退单。
- **核心表**：`expense_claim`、`expense_item`、`expense_standard`
- **关键流程**：草稿 → 提交（触发飞书审批）→ 财务审核（票据/标准/预算）→ 终审 → 待付款 → 已付款 → 已入账。
- **边界**：不做凭证；不做银行支付。

### 5.3 payable 应付与付款
- **职责**：应付台账、付款申请、三单匹配、付款计划、供应商对账、账龄。
- **核心表**：`payable`、`payment_request`、`payment_plan`、`supplier_statement`
- **关键流程**：发票登记生成应付 → 付款申请 → 三单匹配（合同/验收/发票）→ 审批 → 付款执行（U 盾）→ 回单上传 → 销账。
- **边界**：不代替 U 盾付款。

### 5.4 receivable 应收与往来
- **职责**：应收台账、账龄自动计算、到期提醒、回款登记、坏账核销、员工借款、备用金、预付款。
- **核心表**：`receivable`、`collection`、`loan`、`petty_cash`、`prepayment`、`bad_debt`
- **关键流程**：合同/发票生成应收 → 到期前 15 天提醒 → 回款登记销账 → 超期升级；离职前借款结清校验。
- **边界**：不做催收外呼，不代替业务谈判。

### 5.5 contract 合同台账
- **职责**：合同关键字段、财务联附件、到期提醒、财务会签记录。
- **核心表**：`contract`、`contract_party`、`contract_amendment`
- **关键流程**：合同登记 → 财务会签 → 生效 → 付款/开票引用 → 到期前 30 天提醒。
- **边界**：不做合同起草与法律审核；合同原件归档在行政。

### 5.6 budget 预算
- **职责**：年度预算编制、项目/科目/月分解、执行监控、超预算审批、预算调整。
- **核心表**：`budget`、`budget_line`、`budget_adjustment`、`budget_usage`
- **关键流程**：编制 → 审核 → 发布 → 分解 → 报销/付款时实时扣减 → 超预算走调整审批。
- **边界**：不做经营目标制定。

### 5.7 project 项目核算
- **职责**：项目主数据、直接成本归集、间接费用分摊、收入匹配、毛利计算、项目损益。
- **核心表**：`project`、`project_cost`、`project_allocation`、`project_margin`
- **关键流程**：立项建项目号 → 费用/付款挂项目 → 月末归集 → 分摊间接费 → 匹配收入 → 出毛利。
- **边界**：不做项目排期与交付管理。

### 5.8 revenue 收入
- **职责**：收入确认台账、开票联动、到款核销、收入类型判定（技术开发/设计直播/代运营服务费）。
- **核心表**：`revenue_record`、`revenue_type`、`revenue_recognition`
- **关键流程**：合同/结算单 → 收入确认判定 → 台账登记 → 开票申请 → 到款核销。
- **边界**：不做销售线索与商务谈判。

### 5.9 invoice 发票
- **职责**：销项/进项发票登记、验真、勾选认证记录、红冲/作废、开票申请。
- **核心表**：`invoice`、`invoice_item`、`invoice_verification`
- **关键流程**：录入（AI 抽取）→ 校验（抬头/税号/金额）→ 查重 → 登记 → 进项认证提醒。
- **边界**：不直连电子税务局开票。

### 5.10 tax 税务
- **职责**：税种与申报日历、申报台账、税款台账、完税凭证、税收政策库、税务风险事项跟踪、汇算清缴记录。
- **核心表**：`tax_type`、`tax_calendar`、`tax_filing`、`tax_payment`、`tax_policy`、`tax_risk`
- **关键流程**：日历生成申报提醒 → 计算税额 → 申报登记 → 缴款登记 → 完税凭证归档 → 风险事项闭环。
- **边界**：不代替电子税务局申报。

### 5.11 ledger 会计核算记录
- **职责**：凭证台账（摘要级）、科目映射、月结检查清单、金蝶核对导出。
- **核心表**：`voucher_record`、`subject_mapping`、`month_close_checklist`
- **关键流程**：业务单据 → 生成"待入账清单" → 人工在金蝶制证 → 回填凭证号 → 月结检查。
- **边界**：**不生成凭证、不做总账、不做法定报表**（R01/C2）。

### 5.12 archive 档案
- **职责**：会计档案目录、借阅登记、保管期限提醒、销毁清册、财务制度分模块上传。
- **核心表**：`archive_item`、`archive_borrow`、`archive_destruction`、`regulation`
- **关键流程**：归档登记（类型/期间/册数/期限/位置）→ 借阅申请审批 → 到期提醒 → 销毁审批。
- **边界**：不做公司档案体系统管（行政负责）。

### 5.13 control 内控

- **核心表**：`control_check`、`control_finding`、`rectification`
- **关键流程**：检查计划 → 执行记录 → 发现问题 → 整改 → 复核关闭。
- **边界**：不做外部审计。

### 5.14 collab 协作

- **核心表**：`collab_request`、`assigned_task`
- **边界**：不做通用 OA 任务系统。

### 5.15 digital 数字化

- **核心表**：`data_quality_check`、`backup_log`、`system_request`、`system_config`

## 6. 接口设计

### 6.1 飞书免登录（扫码）

```
[浏览器] 打开 /login
   ↓ GET /api/auth/feishu/qr
[中台] 调飞书生成登录二维码 → 返回 qr_url + state(随机, 存 5 分钟)
[浏览器] 渲染二维码
   ↓ 手机飞书扫码确认
[飞书] 回调 GET /api/auth/feishu/callback?code=xxx&state=xxx
[中台] 校验 state → code 换 user_access_token → 拉用户信息
       → 匹配 user 表 → 会话 JWT（httpOnly Cookie, 8h）
       → 未注册用户：拒绝，提示"请联系管理员开通"
```

- 会话：JWT + httpOnly + SameSite=Lax，8 小时；敏感操作二次校验角色。
- 角色**不由飞书决定**，中台内维护（D3）。
- 组织同步：定时任务每小时 + 事件订阅，写入 `user`，只做"存在性"与"在职状态"。

### 6.2 OA 审批双向

```
创建：POST /open-apis/approval/v4/instances
       body: approval_code, user_id(申请人), form(JSON)
       ← instance_code 落库
回写：飞书事件 approval_instance（STATUS_CHANGED）
       → 校验签名 → 按 instance_code + event_id 幂等
       → 更新 approval_instance 状态 → 推进业务状态机
兜底：POST /api/v1/approvals/:id/sync  手工拉取飞书状态
```

- 状态机：`draft → submitted → dept_approved → finance_approved → approved → paid → posted`，旁路 `rejected` / `cancelled`。
- 中台是状态**唯一真相源**；飞书仅通道（D4）。

### 6.3 网盘映射

```
目录规则：/<root_token>/<yyyy>/<MM月>/
         例：/2026/10月/
上传：POST /open-apis/drive/v1/files/upload_all
建夹：POST /open-apis/drive/v1/files/create_folder
定时：每日 02:00 扫描 attachment.sync_state='pending'
      → 失败重试 3 次 → 'failed' + 飞书告警
```

### 6.4 APL 大模型

| 场景 | 输入 | 输出 | 落库 |
|---|---|---|---|
| 发票抽取 | 发票 PDF/图片 | 结构化要素 JSON | `ai_extraction`，人工确认后写 `invoice` |
| 合同抽取 | 合同 PDF | 金额/账期/付款条件/发票类型 | 同上，确认后写 `contract` |
| 税务风险提示 | 税种+期间+金额组合 | 风险项与依据 | 写 `tax_risk` 待确认 |
| 报表解读 | 报表数据 JSON | 分析文字 | 只展示，不落库 |

- 统一抽象 `AiProvider`：`extractInvoice` / `extractContract` / `assessTaxRisk` / `explainReport`。
- **AI 结果一律不直接落账**，必须人工确认（D10）。
- 超时 30s，失败降级为手工录入，不阻断主流程。

### 6.5 内部 API 约定

| 项 | 约定 |
|---|---|
| 风格 | RESTful，`/api/v1/<domain>/<resource>` |
| 响应 | `{ code: 0, message: "ok", data: T, requestId: "..." }` |
| 分页 | `page`（从 1）、`size`（默认 20，上限 200），返回 `total` |
| 错误码 | 4xxxx 客户端；5xxxx 服务端；`40x01` 权限不足；`40901` 状态冲突 |
| 幂等 | 写接口支持 `Idempotency-Key` 头，24 小时去重 |
| 时间 | 一律 ISO8601 + `+08:00`，服务端计算，前端不改时区 |
| 金额 | 一律 `numeric(18,2)`，禁止浮点；前端展示千分位 |
