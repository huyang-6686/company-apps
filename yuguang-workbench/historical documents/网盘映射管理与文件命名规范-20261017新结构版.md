### 2. 每个模块文件夹内部结构（三级模块 → 四级）

以"1. 办公行政管理"为例：

```
1. 办公行政管理/
├── 0. 办公行政管理制度操作模板历史版本汇总/   ← 固定 0 号，归档失效/历史制度模板
├── 1. ××事项执行文件/                        ← 有几个事项就建几个，从 1 起编号
├── 2. ××事项执行文件/                           （对应应用三级菜单）
├── 3. ××事项执行文件/
├── （生效制度①，平铺在模块根目录）            ← 生效制度不进子文件夹
└── （生效制度②，平铺在模块根目录）
```

### 3. 模块内部存放规则

1. **0 号历史汇总**：每个模块文件夹内的第一个文件夹固定为"0.〔模块名〕制度操作模板历史版本汇总"，只存放失效、历史版本的制度与操作模板。
2. **事项执行文件夹**：有几个事项就建几个，从 1 开始按 1 / 2 / 3 / 4 顺序编号（对应应用三级菜单），统一存放该事项的执行文件——包括手动上传附件、AI 生成报告、导出的表格/图片/PDF、自动同步文件。
3. **生效制度平铺**：该部门上传并生效的所有制度，以平铺方式直接放在模块文件夹根目录，与 0 号历史汇总、各事项文件夹并列，不进入任何子文件夹。
4. **旧版本自动归集并改名**：制度一旦失效，旧版本自动移入 0 号历史版本汇总，并按失效命名规则改名（标注"已失效+日期"）；删除则云盘同步删除，进入应用回收站保留 30 天。

## 五、文件命名规则（沿用现行，不变）

| 类型 | 命名规则 | 示例 |
| --- | --- | --- |
| 文件夹 | 应用名 + 数字前缀（1. 2. 3. …），从上往下统一、编号固定 | 1. 品牌部 |
| 页面生成 / 导出文件 | 事项名称 + 版本号 + 日期 | 组织架构图（含人员）-v1-20260830 |
| 员工档案文件 | 编号.工号-姓名+文件类型-日期 | 1.YG001-胡杨应聘简历-20260830 |
| 通用要求 | 一律不带公司名称；主体简称"与光"，禁写"宇光/雨光" | — |
| 管理文件（制度/模板） | 以上传时原始文件名为准，系统不自动改名；失效时标注"已失效+日期" | xx管理办法（已失效20261012） |
| 失效版本 | 自动移入"0.xx模块制度操作模板历史版本汇总" | — |
| 删除版本 | 云盘同步删除，进入应用回收站保留 30 天 | — |
| 订单库文件 | 命名规则后续单独制定 | — |
