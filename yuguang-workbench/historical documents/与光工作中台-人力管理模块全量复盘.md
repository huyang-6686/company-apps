## 二、数据共享主干（跨页面联动关系）

人力所有页面围绕以下主数据链联动，改动一处会牵动多处：

| 主数据 | 源头页面（产生） | 被哪些页面引用（共享） | 关联键 / 机制 |
|---|---|---|---|
| 员工 `employee` | 员工管理（花名册 + 飞书同步） | 岗级薪资、人事档案、培训、绩效、薪资核算、考勤、社保、入转调离、面谈、争议、招聘（入职）、仪表盘 | `employeeId`；与登录账号 `sys_user` 经**手机号 phone** 关联 |
| 组织架构 `org_structure` | 员工管理（飞书一键同步） | 人事档案、岗位说明（同步部门）、入转调离（调岗部门）、权限（部门数据范围） | 部门 id；`sync-from-org` |
| 薪资标准 / 规则 `salary_standard` / `salary_rule` | 岗级薪资（发布生效版） | 薪资核算（按标准 + 规则算薪） | 生效版本号 |
| 考勤 `attendance_record` | 考勤管理（飞书考勤同步） | 薪资核算（同步考勤参与算薪） | 员工 + 月份 |
| 岗位 / 考核指标 `position_description` / `assessment_indicator` | 岗位说明、考核指标库 | 月度考核（同步岗位指标）、绩效 | 岗位名 |
| 绩效 / 人效 `monthly_performance` / `efficiency_report` | 月度考核、绩效分析 | 绩效分析、人效分析、项目奖金（规划中） | 员工 + 月份 |
| 简历 → 员工 `resume → employee` | 招聘 - 简历（待入职 / 转人事档案） | 员工管理（生成员工、回传入职附件） | 待入职 → 入职 |
| 合同 `contract_history` | 员工管理（续签 / 到期） | 法务（合同模块） | 员工 |
| 处罚 `penalty_rule` / `penalty_record` | 关系维护 - 处罚 | 绩效扣分（`mp_penalty_item`） | 员工 |
| 管理文件 `module_file` | 各模块"管理文件" | 全模块共用一套云盘组件 | 按 moduleKey 隔离 |

**外部依赖总览：**
- 飞书：组织架构 / 通讯录同步、考勤同步、入职与调岗审批、消息通知（急招提醒、培训通知、催反馈）、云盘（全部文件归档）。
- AI（DoubaoAiService）：岗位说明书上传识别、招聘月报、培训效果报告、绩效月报、人效 / 人事变动月报。
- 定时任务：每日档案完整性检查、急招岗位提醒、培训资料清理、月初月度计划批量生成、各类月报。
- 双租户：轻立方（默认）与与光（仅同步望向山部门至"经营部-望向山"）。

## 九、复盘结论

### 已实现且数据贯通的链路
1. 飞书 → 组织架构 / 员工 → 档案 / 岗级 / 绩效 / 薪酬 / 考勤 / 社保（员工是全模块主轴）。
2. 飞书考勤 → 考勤异常 → 薪资核算 → 人效分析。
3. 岗位说明书 → 考核指标 → 月度考核（三级审批）→ 绩效分析。
4. 简历待入职 → 员工档案（附件回传）。
5. 调岗 → 飞书审批 → 人事变动月报。

### 未完成 / 风险点（如实标注）
- ❌ **项目奖金**：整页占位，未开发。
- ⚠️ **薪资核算**：含 FeaturePlaceholder，部分子功能未完全实现。
- ⚠️ **入转调离的飞书审批为"手动点同步"**，不是事件自动触发。
- ⚠️ 数据权限全在**应用层**（无数据库行级安全 RLS），合并时需重点核对员工 / 部门可见范围。
- ⚠️ 员工与登录账号靠 **手机号** 关联，而非统一 user_id，三应用合并时这是主数据打通的关键风险点。
