## 二、第一层：飞书底座

飞书是整个体系的基础设施层，提供四项能力：

| 能力 | 说明 |
| --- | --- |
| 组织架构同步 | 飞书通讯录为唯一组织架构源头，统一同步到与光工作中台，再由工作台分发到各应用 |
| IM | 即时通讯、消息通知、审批提醒，各应用通过飞书机器人推送消息 |
| 网盘映射规则存档云盘 | 《网盘映射管理与文件命名规范》正式版存档于飞书云盘，各应用以云盘中的最新正式版为唯一归口依据 |
| OA 审批 | 飞书 OA 承载所有正式审批流程；审批字段根据各应用需求反向定制；审批数据统一同步到与光工作中台后分流到各应用 |

### OA 审批字段反向定制机制

1. 各应用提出审批需求（表单字段、流程节点、审批人规则），提交到与光工作中台。
2. 与光工作中台汇总后，在飞书 OA 中反向定制对应审批模板和字段。
3. 审批数据产生后，统一同步到与光工作中台，再按应用归属和权限分流。
4. **各应用内部不做审批开发**，只做审批数据的接收、展示和基于数据的分析处理。

## 三、第二层：与光工作中台（核心管理平台）

### 职责

与光工作中台是六大管理（人力、行政、财务、法务、项目、经营）的核心数据通道，承担四项平台职能：

1. **组织架构与角色权限标准**
   - 接收飞书同步的组织架构。
   - 在工作台内设置角色和权限标准。
   - 将角色权限标准同步给各应用，各应用按标准落地权限控制，不自建权限体系。
2. **OA 审批数据同步与分流**
   - 接收飞书 OA 审批数据。
   - 根据应用归属和权限，将审批数据分流到对应应用。
   - 各应用基于分流的审批数据做分析和问题解决。
3. **大模型 API 总接口**
   - 工作台统一管理大模型 API 接口，作为全体系唯一的大模型调用入口。
   - 各应用不直接对接大模型服务商，统一通过工作台总接口调用，便于计费、审计、模型切换和提示词管理。
4. **六大管理数据通道**
   - 人力、行政、财务、法务、项目、经营六大管理的数据标准、流转和汇总由工作台承载。
   - 各应用产生的业务数据按第六节菜单层级规则归属到对应模块，跨应用数据交换只通过工作台通道，不直接互读数据库。

## 四、第三层：工具层

| 应用 | 职责 | 归口 |
| --- | --- | --- |
| 知识库 | 承载灯塔知识库，组织知识沉淀、检索和学习 | 租户轻立方 / 个人网盘 / 2. 灯塔知识库 |
| 品牌生产中枢 | 品牌内容生产、物料管理 | 租户轻立方 / 中台网盘 / 4. 品牌部（与光品牌中枢） |
| 星窗展示台 | 对外展示、窗口内容管理 | 按网盘映射规范正式版归口 |

工具层应用从工作台接收角色权限标准和分流的审批数据，产生的业务数据通过工作台通道回流。

## 五、第三层：业务层

### 1. 望向山经营中台

- **定位**：独立经营实体，与旅行社同级。
- **租户**：租户与光。
- **网盘归口**：租户与光 / 云盘根 / 望向山中台网盘。
- 2 级、3 级子目录按梳理后的业务大类定稿后发布新版网盘映射规则。

### 2. 镇安生态产业协会管理中台

- **定位**：特大项目专项，与订单库平级。
- **租户**：租户轻立方。
- **网盘归口**：租户轻立方 / 中台网盘 / 3. 业务部 / 1. 项目部 / 2. 镇安生态产业协会管理中台。
- 2 级、3 级子目录按业务大类梳理后定稿。

### 3. 镇安应用特殊需求（本次确认）

1. **非飞书租户登录**：镇安应用需要支持非飞书租户用户登录使用，不能依赖飞书通讯录作为唯一账号体系。
2. **钉钉 OA 接入**：镇安应用需要接入钉钉 OA，承载其正式审批流程；审批数据接入后仍按「数据统一进工作台分流」的原则回流到与光工作中台，与其他飞书 OA 数据在分流层统一处理。

> 待确认项：镇安应用的登录方案（独立账号体系 / 微信扫码 / 钉钉扫码）和钉钉 OA 审批模板是否独立于飞书 OA 单独定制，需要单独论证后在定稿版明确。

## 六、通用约束

1. **组织架构单一源头**：飞书通讯录是唯一组织架构源头（镇安应用的补充账号体系除外），任何应用不维护第二份组织架构主数据。
2. **权限不自建**：各应用的角色权限以与光工作中台下发的标准为准，应用内只做权限的落地执行，不做权限标准和角色定义。
3. **审批不内建**：各应用内部不做审批流程开发，审批统一走飞书 OA（镇安走钉钉 OA），应用只接收审批结果数据。
4. **大模型调用统一入口**：所有大模型调用走与光工作中台总接口，各应用不直连大模型服务商。
5. **网盘归口严格映射**：所有文件归档严格按《网盘映射管理与文件命名规范》最新正式版执行，规则变更走「自动起草新版草稿 → 人工审核 → 发布正式版」流程。
6. **菜单层级规则**：各应用菜单按《网盘映射管理与文件命名规范》第六节「菜单层级映射规则（最终版）」执行，1级大类 / 2级模块 / 3级事项 / 4级科目，禁止 5 级。
7. **跨应用数据交换**：只通过与光工作中台的已批准接口合同交换，不直接读取其他应用数据库。
