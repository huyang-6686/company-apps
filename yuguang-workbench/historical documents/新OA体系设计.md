# 与光工作中台·新 OA 体系设计（v1）

**用途**：供 Codex 新应用合并 OA 需求；作为新 OA 全部新建的标准蓝图。
**总策略**：
- 历史 OA **一个不删、全部保留、历史数据不动**。
- 新 OA **全部重新上线**，统一命名（不再用"（新）"后缀），按职能域分组。
- 每个 OA 对应一个明确的业务类型，**不同类型解决不同问题，不重复、不遗漏**。
- 新体系确认无误、员工迁移完成后，再逐步下架旧 OA（旧数据始终保留）。

---

## 一、设计原则

1. **一个类型一个 OA**：同一业务问题只走一个入口，杜绝同名多模板。
2. **公共字段统一**：公司主体、费用科目、项目明细、附件、说明全体系口径一致。
3. **条件必填**：关联审批、备用金、采购等仅在满足条件时出现并必填，不设无条件必填。
4. **边界清晰**：每个 OA 明确"处理什么、不处理什么、谁发起、谁审批"。
5. **兼容飞书控件**：考勤（加班/补卡/出差）、人事（转正/调岗/离职）优先用飞书标准控件。

## 三、公共字段规范（所有 OA 统一）

### 3.1 申请单位（公司主体）
- 统一字段名：**"申请单位"**；控件：**单选**（一次申请归属一个主体）。
- 例外保留多选：薪酬发放、税款缴纳、股东及企业往来（天然涉及多主体）。
- 选项统一引用标准主体清单（需确认有效主体）：
  西安轻立方企业管理咨询有限公司 / 陕西与光星际科技有限公司 / 陕西数播科技有限公司 / 西安叁棱镜网络科技有限公司 / 西安知涯文化创意有限公司 / 陕西事盈科技有限公司（凯联、元之宙、弘焰、头号视觉等是否保留待确认）。

### 3.2 费用科目
- 统一字段名：**"费用科目"**；选项统一：
  福利费 / 办公费 / 业务招待费 / 交通费 / 差旅费 / 物业费 / 通讯费 / 快递物流费 / 中介机构服务费 / 汽车费用 / 会议费 / 房租 / 租赁费 / 研发费 / 员工培训费 / 招投标费用 / 利息费用 / 劳务费 / 技术服务费 / 施工费 / 其他。

### 3.3 项目明细
- 统一为一个明细控件，只保留 3 列：**项目年份、立项名称、唯一码**；删除重复堆叠的立项/唯一码组。

### 3.4 说明、附件
- 说明字段用业务名（如"请假事由""付款说明"），禁止"说明1/2/3"。
- 附件统一命名"相关附件"或具体业务名（如"发票及凭证"）。

### 3.5 条件必填
- 关联审批、备用金、采购、紧急付款、发票等字段：选对应类别才显示、才必填。

## 五、迁移与下架步骤

1. 在飞书审批后台按本方案**新建 29 个 OA**（注：审批定义不支持 API 建条件分支，需在后台手动配置）。
2. 先小范围测试每个 OA 的字段、条件、流程。
3. 逐类通知员工改用新 OA，旧 OA 设为"仅管理员可见"或停用发起。
4. 全部迁移完成后下架旧 OA；**旧 OA 与历史数据永久保留，不删除**。
5. 与光租户按相同 29 个 OA 配置，跨租户发起关联轻立方审批。

## 六、待确认事项

1. 有效主体清单：凯联、元之宙、弘焰、头号视觉等是否保留为选项。
2. 费用科目是否需要增减（如"折旧费""服务费"等）。
3. 合同评审、预算管控、客户/供应商准入、公章外带是否纳入本期新建范围。
4. 行政后勤事务（快递/报修/名片）是否合并为一个 OA，还是各自独立。
5. 物资领用是否并入"固定资产及设备领用归还"或独立。
6. 年假/调休额度是否需要独立管理，还是仅作为请假时的额度校验。
7. 29 个 OA 的审批金额分级阈值（如超多少走总经办）。
