# 应用开发流程规范

- **版本**：v1.0（2026-10-20）
- **状态**：正式版
- **适用范围**：与光工作中台、工具层、大项目应用、经营实体应用及其接入应用
- **定位**：本规范是所有应用建设、上架、接口开发、通知配置和联调验收的**流程层强制规范**，与《组织架构管理规范》《应用搭建结构规范》《网盘映射管理与文件命名规范》《任务发布与管理规范》《统一信息通知与应用消息通道规范》《任务接口合同》共同构成完整规范体系。内容冲突时，业务规则以各业务规范为准，流程和顺序以本规范为准。
- **执行顺序**：本规范与五份业务规范同步生效；已接入应用按本规范补齐流程缺口，新建应用从规范读起。

## 一、规范体系与优先级

### 1.1 规范体系

| 序号 | 规范 | 职责 |
| --- | --- | --- |
| 1 | 组织架构管理规范 | 统一组织架构、统一员工 ID、租户来源与人员授权 |
| 2 | 应用搭建结构规范 | 五层架构、应用定位、菜单规则、建设约束 |
| 3 | 网盘映射管理与文件命名规范 | 附件归档、文件命名、版本与审计 |
| 4 | 任务发布与管理规范 | 任务类型、发布方向、状态闭环、验收规则 |
| 5 | 统一信息通知与应用消息通道规范 | 通知中心、机器人路由、深链、失败补偿 |
| 6 | 任务接口合同 | 任务接口、事件回调、幂等与错误码 |
| 7 | 与光任务功能配置启动清单 | 工作台与应用的启动配置项 |
| 8 | 五份规范一致性自检记录 | 规范冲突核查结论 |
| 9 | 本规范（应用开发流程规范） | 开发流程、阶段划分、验收与发布顺序 |

### 1.2 优先级规则

1. **用户明确业务指令 > 本规范 > 业务规范细节**；业务规范之间冲突时，提交工作台接口注册表负责人裁定，不得自行修改规则。
2. 本规范只管理"怎么做、按什么顺序做、做到什么程度算完成"，不重新定义任务状态机、通知字段或网盘路径。
3. 规范冲突时，必须先提交问题、影响范围和建议方案，经确认后统一修订。

## 二、开发阶段总流程

每个应用的建设必须按以下六个阶段顺序执行，禁止跳阶段。

```text
阶段0 规范确认
  → 阶段1 需求与设计评审
  → 阶段2 开发准备
  → 阶段3 开发实现
  → 阶段4 演示版测试（Demo 验收）
  → 阶段5 最终成型（一次成型制作）
  → 阶段6 联调验收与上线

```

### 2.1 阶段0：规范确认

- [ ] 阅读并确认本规范及五份业务规范的最新正式版。
- [ ] 确认应用分层定位（工具层 / 大项目 / 经营实体）和租户承载。
- [ ] 确认 application_id、模块 ID、应用负责人、接口负责人。
- [ ] 确认可接收的任务类型和模块范围。
- [ ] 确认组织、应用、模块、项目、实体授权映射。

**阶段出口**：应用负责人在《应用开发流程规范》附表登记"规范确认完成"。

### 2.2 阶段1：需求与设计评审

- [ ] 明确业务目的、目标用户、成功标准。
- [ ] 明确与任务、通知、网盘、组织架构的交互点。
- [ ] 输出《需求与设计文档》，至少包含：功能清单、数据流、权限矩阵、菜单结构（四级以内）、通知事件清单、深链清单、附件归档路径。
- [ ] 与光工作中台负责人评审通过后，进入阶段2。

**阶段出口**：《需求与设计文档》评审通过并归档到应用网盘映射目录。

### 2.3 阶段2：开发准备

- [ ] 准备独立项目目录，禁止直接拼接历史应用源码；历史应用仅作为需求和运行证据。
- [ ] 准备测试账号、联调环境和测试数据。
- [ ] 完成对应租户飞书机器人配置（企业自建应用，不共用机器人凭证）。
- [ ] 确认网盘映射目录（按最新版网盘映射规范）。
- [ ] 准备请求签名、幂等键、重试和失败补偿机制的技术方案。

**阶段出口**：机器人配置完成、联调环境可用、网盘映射目录确认记录归档。

### 2.4 阶段3：开发实现

- [ ] 按《需求与设计文档》实现业务功能。
- [ ] 实现统一信息通知板块（未读、待办理、已处理、逾期、全部通知）。
- [ ] 实现任务、轻审批、工作流和异常事件接口。
- [ ] 实现 notification.created / notification.updated / notification.expired 事件接收。
- [ ] 实现已读、待办理、已处理和发送结果回传。
- [ ] 实现每类通知的具体办理深链。
- [ ] 实现请求签名、幂等、去重、重试和失败补偿。
- [ ] 配置审计日志，不记录机器人凭证、访问令牌和附件原文。

**阶段出口**：代码完成并通过开发自测，可进入演示版测试。

### 2.5 阶段4：演示版测试（Demo 验收）

- [ ] 部署演示版到联调环境。
- [ ] 走通主业务流程（从发布到办理反馈）。
- [ ] 验证通知板块、深链、机器人消息、权限校验、附件下载日志。
- [ ] 发现的问题按严重程度分级：P0（阻塞）、P1（功能缺陷）、P2（体验问题）。
- [ ] P0、P1 全部修复并复测通过。

**阶段出口**：演示版测试通过，问题清单归档。**演示版测试通过不等于可上线**，必须继续阶段5、6。

### 2.6 阶段5：最终成型（一次成型制作）

演示版验证通过后，将完整规范和演示验证结论作为输入，交给指定模型一次性完成最终代码成型。该阶段的输入必须包含：

- [ ] 五份业务规范 + 本规范的最新正式版。
- [ ] 《需求与设计文档》。
- [ ] 演示版测试问题清单及修复记录。
- [ ] 明确的验收标准（对应阶段6的验收场景）。

执行要求：

1. 最终成型必须使用与演示版相同的规范输入，不得在成型阶段引入新需求。
2. 成型过程中如发现规范冲突或规范未覆盖的场景，**停止成型**，按"规范冲突处理"流程提交问题，不得自行决定。
3. 成型完成后按阶段6验收场景逐条核验。

**阶段出口**：最终代码成型完成，进入联调验收。

### 2.7 阶段6：联调验收与上线

按五份业务规范和通知规范的强制验收场景逐条执行，至少覆盖：

- [ ] 与光发布任务后，本应用通知板块出现待办理通知。
- [ ] 本应用自己的飞书机器人向对应租户本人发送消息。
- [ ] 点击机器人消息直接进入本应用具体办理页面。
- [ ] 应用内完成接收、办理、反馈和验收后，通知状态同步更新。
- [ ] 轻审批和工作流节点可进入应用通知板块和与光总通知。
- [ ] 截止、逾期、自动转派和逾期总览状态正确。
- [ ] 多租户员工收到正确租户账号的消息。
- [ ] 无权限人员不能查看通知详情或打开业务页面。
- [ ] 重复事件不会重复生成通知。
- [ ] 机器人失败时应用内通知仍保留，并可重试和补偿。
- [ ] 附件权限、网盘链接和下载日志符合规范。
- [ ] 离职或账号失效后停止新消息投递，历史记录按规范保留。

**上线门槛**：以上全部通过 + 接口合同测试通过 + 权限矩阵核验通过 + 网盘映射核验通过 + 审计日志核验通过。应用负责人和与光负责人共同确认后接入。未完成机器人、通知板块、具体办理深链、权限校验和接口联调的应用，不得开启生产通知和生产任务接入。

## 三、通用开发约束

1. **组织主数据**：使用与光工作中台统一组织架构和统一员工 ID，不建立第二套组织主数据。
2. **双租户身份**：保留租户来源、登录入口和对应飞书 user_id，不跨租户转发消息。
3. **数据边界**：跨应用数据只通过工作台批准的接口交换，禁止直接读取其他应用数据库。
4. **业务责任**：各应用独立负责自己的业务页面、业务状态和办理流程，工作台只做汇总、路由、统计和审计。
5. **任务类型**：固定为日常任务、经营任务、项目任务；协作部门/协作人为选填字段，不单独建立协作任务类型。
6. **任务方向**：支持向下发布和同级协作，不支持向上发布和下属辐射。
7. **验收驳回**：任务提交后由发布人验收，驳回必须填写原因。
8. **附件归档**：任务附件和业务正式文件按网盘映射规范归档，不建设独立对象存储。
9. **通知路径**：与光统一汇总，来源应用投递，来源应用办理；工作台机器人不代替来源应用发送业务通知。
10. **菜单规则**：1 级业务大类、2 级模块、3 级事项、4 级科目；1 级只折叠 2 级，禁止 5 级。
11. **禁止事项**：禁止把业务办理页面复制到与光工作台；禁止机器人消息只跳转到与光通知中心；禁止绕过统一员工 ID、租户路由和应用权限校验；禁止将业务附件存入未批准的对象存储。
12. **规范冲突**：发现冲突先提交问题、影响范围和建议方案，不得自行修改规则。

## 四、模型使用与风险控制

1. **模型可替换**：本规范不绑定特定模型；演示版和最终成型可使用不同模型，但必须使用同一套规范输入。
2. **提示词即规范**：交给模型的提示词必须直接引用规范文件，不复述摘要；摘要和原文冲突时以原文为准。
3. **成型不等于验收**：模型产出必须经过阶段6验收场景核验，不得以"模型说完成了"代替测试通过。
4. **演示版与正式版隔离**：演示版仅供验证思路和流程，演示版代码不得直接当作最终代码；最终成型必须重新生成或显式确认演示版代码质量达标。
5. **失败回退**：最终成型失败或验收不通过时，回退到阶段3或阶段4，补充设计或修复演示版后再次成型。

## 六、发布与实施

本规范作为应用开发流程的正式规范发布，与五份业务规范同步执行。规范库统一存放在 E:\company-apps\Standard Library，命名规则为 规范名称-日期-版本号（日期 YYYYMMDD，版本号 v主版本.次版本）。规范修订时同步更新版本号和日期，并在本规范"发布与实施"章节记录变更。
