# 任务发布与管理规范

- **版本**：v1.0（2026-10-20）
- **状态**：正式版
- **适用范围**：与光工作中台、工具层、大项目应用和经营实体应用中的任务发布、同步、办理与统计
- **配套文件**：《任务接口合同-20261020正式版》《与光任务功能配置启动清单-20261020》
- **通知规则**：任务通知遵循《统一信息通知与应用消息通道规范-20261020正式版》

## 一、定位与建设边界

任务管理是与光工作中台的统一任务汇总能力。与光工作中台提供发布入口、统一任务记录、权限校验、通知、状态闭环和统计；对应应用提供本应用任务看板、业务办理入口和结果反馈。

任务必须归属一个应用，模块可以为空。工作台是跨应用任务的汇总层，应用是本应用任务的办理层。应用之间只能通过本规范配套的接口合同交换任务数据，不得直接读取其他应用数据库。

本规范覆盖内部人员任务，不覆盖外部人员、跨组织外部任务、部门任务池、角色任务池、子任务和跨组织任务。

## 二、与组织、应用和网盘规范的衔接

1. **组织架构**：接收人来自与光工作中台统一组织架构；选人范围先按应用授权过滤，再按模块授权过滤。任务不建立第二套组织树。
2. **应用架构**：任务应用范围覆盖工作台模块、工具层、大项目应用和经营实体应用。应用内看板只显示本应用相关任务。
3. **角色逻辑**：组织角色决定默认管理范围，应用角色决定具体应用、项目、实体和模块权限。任务发布权限采用角色开关配置，不以职级硬编码。
4. **双租户**：轻立方和与光人员可以在同一工作台内按授权协作；任务协作不等同于双租户主数据合并。
5. **网盘**：任务附件归档到任务所属应用的正式网盘映射位置。工作台保存文件元数据、定位索引和权限日志，正式文件以飞书网盘文件为准，不建设独立对象存储。

## 三、任务类型和任务关系

任务类型固定为三类：

| 类型 | 适用范围 |
| --- | --- |
| 日常任务 | 职能部门日常工作、例行事项和临时工作安排 |
| 经营任务 | 经营实体指标、经营动作和经营事项 |
| 项目任务 | 一般项目或特大项目的推进、阶段性交付和项目事项 |

管理工作归入职能部门的日常任务；协作不是独立任务类型。任务可以记录协作部门和协作人，协作部门/协作人是可选字段，用于发布时提出协作要求；不填写时由接收人自行决定是否协作。

### 3.1 支出意向登记轻审批

“支出意向登记”是与光工作中台及接入业务应用中的独立轻审批对象，不新增采购 OA。它用于采购或支出发生前的事项、责任、时间和采购方式留痕；审批通过后，报销和公司对公付款仍按飞书 OA 办理。挂账/他人代付（无需公司结算）的事项只在工作台登记结清，不强制关联付款 OA。

- **发起入口**：个人工作台统一发起日常费用和小项目支出；大项目从对应项目应用发起并自动关联项目 ID；经营支出从对应经营实体应用发起并自动关联应用 ID。
- **业务路由**：日常费用由行政处理；小项目由项目负责人处理；大项目由来源项目应用负责；经营实体按实体授权路由，当前望向山由公司行政处理。
- **金额规则**：按同一完整事项的预计总额计算，含税费、运费及相关费用；同一事项不得拆分提交。金额低于 200 元由首位负责人审核；金额达到 200 元，首位负责人通过后再送创始人审核。
- **逾期升级**：首位负责人收到后 1 个工作日未处理，升级给创始人；创始人接手后的一次处理即为最终审核，不重复会签。申请人不得审批本人发起的事项，直接转创始人。
- **采购方式**：审批人选择“申请人自行采购”或“公司统一采购”，并填写预计采购时间。项目支出由项目负责人推进统一采购，办公用品可与行政协同；望向山统一采购由行政执行。
- **完成闭环**：采购完成记录实际金额和时间；统一采购由申请人确认收到后完成。预计采购时间到期未完成仅提醒申请人和执行人并标记采购逾期，不重新触发审批。
- **结算方式**：申请人自行垫付关联报销 OA；公司对公付款关联付款 OA；挂账/他人代付（无需公司结算）填写支付方或挂账对象、实际金额和日期后直接记为“已结清（登记）”。
- **字段和权限**：不强制上传报价、截图或预算依据，附件选填。按统一员工 ID、租户、应用、部门、项目和实体授权查看；个人、审批人、执行人、行政、项目负责人和创始人只查看其授权范围。

轻审批对象保留独立字段、状态、审批记录和结算台账；任务模块只承载待办、1 个工作日提醒与逾期升级、统一通知汇总、统计和审计。通知深链必须打开来源应用或工作台的具体支出意向办理页，不把支出意向硬套成普通任务。

## 四、发布权限和任务方向

1. 发布权限由工作台按应用角色配置，管理员可对应用、模块和角色分别开启或关闭。
2. 观察人及只读人员不获得发布权限。
3. 支持向下发布和同级协作发布；不支持向上发布。
4. 项目团队成员之间按项目内平级协作处理。经营实体内，实体负责人（主理人）与实体员工（店员）按实体内平级协作处理。
5. 发布人只能选择自己有权限触达的人员，且接收人必须通过应用和模块授权过滤。

## 五、发布流程和字段

发布流程固定为：**选择应用 → 选择模块（可不选）→ 选择接收人 → 填写任务 → 确认发布**。

### 5.1 应用和模块

- 应用必选，单选；只展示发布人有发布权限的应用。
- 模块可选；不选时任务显示为“应用通用”。
- 选模块后，人员范围按模块授权二次过滤。

### 5.2 接收人

- 按统一组织架构展示部门和人员，组织框架不因任务改变。
- 支持姓名、部门、角色搜索和多人选择。
- 一期最终必须选到具体人；多人发布为多条独立接收任务，每人独立办理和验收。
- 不支持“辐射下属”。发布给部门负责人后，是否向下安排或发起协作由接收人自行决定；后续任务通过正常发布流程建立，可关联来源任务。

### 5.3 任务字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 任务标题 | 是 | 简明描述任务目标 |
| 任务类型 | 是 | 日常任务、经营任务、项目任务 |
| 任务描述 | 是 | 工作内容、要求和交付标准 |
| 优先级 | 是 | 高、中、低 |
| 截止时间 | 是 | 使用统一时区并记录原始值 |
| 接收人 | 是 | 具体人员，可多人 |
| 协作部门/协作人 | 否 | 可多选，可附协作要求 |
| 附件 | 否 | 按应用网盘映射归档 |
| 是否需要反馈结果 | 是 | 默认需要 |

## 六、任务看板和可见范围

### 6.1 与光总看板

总看板至少提供：我发布的、我负责的、与我协作的、应用筛选、模块筛选、任务类型筛选、状态筛选、截止时间筛选和关键词搜索。

普通员工只看与自己相关的任务：自己发布、分配给自己、自己参与协作或由自己发起的关联任务。发布人、接收人和接收人所在部门负责人默认可查看任务详情；其他人员必须获得明确授权。

### 6.2 应用内看板

应用内只显示本应用相关任务，包括从与光工作中台发布到本应用人员的任务。应用内支持查看、接收确认、办理、提交反馈和结果；任务状态、反馈、验收和操作记录通过接口与总看板同步。

### 6.3 菜单层级

遵循四级菜单规则：

```text
工作台（1级业务大类）
└── 任务看板（2级模块）
    ├── 我发布的（3级事项）
    ├── 我负责的（3级事项）
    ├── 与我协作的（3级事项）
    ├── 发布任务（3级事项）
    └── 任务统计（3级事项）
```

应用内任务看板沿用对应应用已有菜单层级，不新增第五级菜单。

## 七、状态和闭环

### 7.1 状态

`待接收`、`进行中`、`待验收`、`已完成`、`已驳回`、`已逾期`、`已取消`。

### 7.2 状态规则

1. 发布后为待接收；接收人确认收到后进入进行中。
2. 接收人提交反馈和结果后进入待验收，提交内容可包含说明、完成时间和附件。
3. 发布人确认通过后进入已完成；确认不通过必须填写原因，任务回到进行中并通知接收人。
4. 超过截止时间未完成时标记已逾期，但不自动关闭；逾期后仍可补交并走验收闭环。
5. 发布人可取消未完成任务，必须填写取消原因；取消后保留历史并通知接收人。
6. 发布人可修改任务内容和截止时间，修改后通知接收人并保留修改前后值。接收人不能修改发布内容。
7. 接收人离职或调岗后，未完成任务自动转派到其部门负责人，并记录自动转派原因、时间和原接收人。

## 八、通知、附件和审计

### 8.1 通知

- 发布时由任务所属应用的飞书机器人通知接收人，并进入与光统一通知中心；
- 截止日前一天提醒接收人；
- 超期后每天提醒接收人和发布人；
- 修改、提交、驳回、确认完成、取消和自动转派时通知相关人员；
- 员工点击任务通知后打开任务所属应用的具体办理页面；与光总通知只做汇总和跳转。

### 8.2 附件

任务附件和结果附件按所属应用映射到飞书网盘；中台保存任务附件的文件 ID、网盘链接、文件名、版本、上传人、上传时间和权限校验结果。附件下载必须执行任务可见范围校验并记录日志。

### 8.3 审计

任务详情提供不可删除的时间线，记录发布、接收确认、进度/反馈、修改、催办、提交、驳回及原因、验收、取消、逾期和转派。任务历史记录不得物理删除。

## 九、统计报表

提供详细统计报表，按人、部门、应用、模块、任务类型和时间段筛选，至少包括：任务总数、完成数、进行中数、逾期数、取消数、响应时长、平均完成时间、逾期率、验收通过率和驳回次数。统计权限遵循总看板权限，敏感明细只向授权管理者展示。

## 十、一期验收标准

1. 任务看板首端可见发布任务入口，应用必选、模块可选。
2. 选人正确执行应用授权和模块授权过滤，无权限人员不可见、不可选。
3. 三类任务可选，支持协作部门/协作人选填字段。
4. 支持向下发布和同级协作，不支持向上发布，不提供辐射下属。
5. 总看板与应用看板同步，应用内只显示本应用任务。
6. 接收人可提交说明和附件，发布人可验收、驳回并填写原因。
7. 支持修改、取消、逾期补交、自动转派和通知规则。
8. 发布人、接收人和部门负责人可按规则查看，普通员工只查看与自己相关任务。
9. 全部操作、状态变化、文件定位和下载记录可审计。
10. 详细统计报表可按人、部门和时间段生成。

## 十一、发布与实施

本规范作为任务管理第四份正式规范发布。与光工作中台负责统一配置任务入口、权限开关、通知策略、状态机、统计口径和接口凭证；各应用按《任务接口合同-20261020正式版》完成任务看板、接收办理、结果反馈和事件回传。任何应用接入前必须完成接口联调、权限测试、幂等测试和审计记录核验。
