# 局域网测试端口与应用目录命名规范

版本：v1.0  
发布日期：2026-10-21  
适用范围：当前同时开发的五个应用  
规范状态：执行规范

## 1. 目的

统一五个应用的本地目录名称、局域网测试端口和生产构建后的启动方式，避免端口冲突、目录名称漂移和启动命令不一致。

## 2. 应用目录名称与端口分配

各应用必须使用下表中的目录名称和固定端口。端口不得自行调整、替换或顺延。

| 应用 | 应使用的文件夹名称 | 固定端口 | 局域网验证地址 |
| --- | --- | ---: | --- |
| 镇安县生态产业协会 | `zhenan-association` | `3000` | `http://192.168.0.101:3000` |
| 望向山经营中台 | `business-wangxiangshan` | `3001` | `http://192.168.0.101:3001` |
| 与光工作中台 | `yuguang-workbench` | `3002` | `http://192.168.0.101:3002` |
| 灯塔知识库 | `lighthouse-corpus` | `3003` | `http://192.168.0.101:3003` |
| 星窗工作台 | `public-showcase` | `3004` | `http://192.168.0.101:3004` |

目录名称以小写英文、数字和连字符为准。应用仓库根目录、部署脚本引用、文档示例和跨应用通知中的应用标识必须保持一致。不得使用临时中文目录名、个人缩写或同一应用的多个别名。

## 3. 启动要求

### 3.1 Next.js 应用

生产构建完成后，`package.json` 必须提供固定端口的 `start:lan` 脚本，形式如下：

```json
{
  "scripts": {
    "start:lan": "npx next start -H 0.0.0.0 -p <固定端口>"
  }
}
```

其中 `<固定端口>` 必须替换为本表分配的端口。示例：镇安县生态产业协会使用：

```json
"start:lan": "npx next start -H 0.0.0.0 -p 3000"
```

### 3.2 非 Next.js 应用

必须使用该框架等价的生产启动命令，明确监听 `0.0.0.0:<固定端口>`。命令必须写入 `package.json` 的 `start:lan`，不得只依赖临时环境变量或手工输入。

## 4. 启动前端口检查

启动前必须检查本应用固定端口是否已被占用。端口被占用时，启动流程必须直接报错并提示端口号及占用情况，不得自动换端口、随机端口或改用其他应用端口。

Windows 检查示例：

```powershell
Get-NetTCPConnection -LocalPort <固定端口> -ErrorAction SilentlyContinue
```

也可使用：

```powershell
netstat -ano | findstr ":<固定端口>"
```

确认端口空闲后，再执行：

```powershell
npm run build
npm run start:lan
```

## 5. 验证、停止与边界

- 启动成功后，从同一局域网访问本应用对应的 `http://192.168.0.101:<固定端口>`。
- 本规范只覆盖本机局域网测试，不配置 HTTPS、域名、数据库、公网访问或端口映射。
- 停止方式：在运行 `npm run start:lan` 的终端按 `Ctrl+C`。
- 若终端已关闭但进程仍在运行，先根据端口查询 PID，再结束对应进程；不得结束其他应用的进程。
- 应用提交或交接时，必须同时核对：文件夹名称、端口、`start:lan`、监听地址和验证地址。
