# 应用搭建结构规范（2026-10-19 更新正式版）

- **版本**：v1.1
- **依据**：2026-10-18 正式版及 2026-10-19 组织架构调整
- **状态**：正式版

## 一、五层总体架构

```text
第一层：飞书底座
  组织架构、免登录、IM、云盘、OA审批、考勤等基础能力

第二层：与光工作中台（核心管理平台）
  统一身份、组织权限、OA数据同步与分流、六大管理数据通道、AI总接口

第三层：工具层
  灯塔知识库、与光品牌中枢/品牌生产中枢、星窗工作台等通用工具

第四层：业务层-大项目
  镇安县生态产业协会管理中台、镇安真味区域公用品牌项目管理中台等特大项目专项

第五层：业务层-经营实体
  望向山（咖啡厅）、特产店、旅拍馆、旅行社
```

## 二、飞书底座

飞书是统一底座，提供通讯录、免登、IM、云盘、OA审批、考勤及开放平台事件能力。与光工作中台只同步和分析 OA 数据，不在应用内部重建 OA 审批；正式审批仍在飞书完成。

### OA 数据边界

各应用提出流程、字段和节点需求，由与光工作中台汇总后反向优化飞书 OA。审批模板、字段、节点、附件、抄送、通知、单据编号、状态变化和历史实例统一同步到工作台，再按应用、租户和权限分流。审批页面、催办和正式执行留在飞书。

## 三、与光工作中台

与光工作中台是统一应用和公司的核心管理平台，承载完整统一组织架构、人力、行政、财务、法务、项目、经营六个业务大类和系统设置。它负责轻立方与与光飞书身份映射、组织节点映射、应用角色下发、OA 数据全量同步、历史附件索引、统一通知汇总、数据分析、审计和统一 AI 接口。轻立方是公司组织架构唯一主数据来源和轻立方侧人员入口；与光租户承载经营实体人员组织节点及望向山正式档案。

工作台不直接修改飞书组织架构和 OA 配置；优化建议由工作台形成清单，管理员在飞书后台执行并回写版本与执行记录。双租户数据合并仅创始人可执行；应用内跨租户协作允许轻立方和与光人员在同一应用内按授权协作。跨应用数据只通过工作台批准的接口合同交换，不直接读取其他应用数据库。

## 四、第三层工具层

| 应用 | 定位 | 权限来源 |
| --- | --- | --- |
| 灯塔知识库 | 知识沉淀、检索、学习和知识节点授权 | 工作台组织角色 + 知识节点授权 |
| 与光品牌中枢/品牌生产中枢 | 品牌生产、素材和本地 5090D 算力工具 | 品牌部高权限 + 其他成员按工具授权 |
| 星窗工作台 | 公网展示和项目分享页面 | 管理端点对点授权，分享页按项目授权 |

## 五、第四层业务层-大项目

大项目具有跨部门、长期经营或外部合作属性，独立建设业务应用，但组织身份、OA 数据、权限标准和基础档案由工作台提供。

| 应用 | 归属 | 说明 |
| --- | --- | --- |
| 镇安县生态产业协会管理中台 | 业务部 → 项目部 | 特大项目专项管理 |
| 镇安真味区域公用品牌项目管理中台 | 轻立方 / 业务部 → 项目部 | 区域公用品牌特大项目专项管理，不归经营部 |

## 六、第五层业务层-经营实体

经营实体统一挂在轻立方 **业务部 → 经营部** 下。经营实体应用独立负责门店/业务执行，经营数据按接口回流工作台汇总；审批仍依赖飞书 OA。

| 实体 | 业务称呼 | 租户归属 |
| --- | --- | --- |
| 望向山 | 咖啡厅 | 与光租户承载；组织映射轻立方经营部；正式档案留在与光“望向山中台网盘” |
| 特产店（原规范称特产馆） | 特产经营 | 与光租户承载；组织映射轻立方经营部 |
| 旅拍馆 | 旅拍经营 | 与光租户承载；组织映射轻立方经营部 |
| 旅行社 | 旅行服务 | 轻立方经营部 |

望向山、特产店和旅拍馆应用由与光租户承载，组织节点映射到轻立方经营部；望向山正式档案留在与光“望向山中台网盘”。各经营实体应用可以独立开发和上架，但必须遵守工作台身份、组织和数据共享规范。

## 七、应用角色和双重逻辑

项目中台和经营中台同时使用组织架构角色与应用授权角色。组织角色说明人员属于哪个部门，应用角色说明其在具体项目或实体中承担什么职责。

- 项目：项目负责人、项目经办人、项目成员、项目支持、项目观察人。
- 实体：经营负责人、经营经办人（主理人）、经营协作人、实体员工（店员）、经营支持（含品牌部）、实体观察人。
- 观察人仅用于外部投资人、顾问、外协等只读访问，按项目、实体或模块点对点授权。

## 八、通用建设约束

1. 飞书通讯录是组织架构唯一来源；应用不维护第二套组织主数据。
2. 所有正式审批走飞书 OA；应用只同步、分析、展示和留痕。
3. 大模型调用统一通过工作台总接口，便于审计、计费、切换和提示词管理。
4. 业务应用使用独立项目和目录，禁止直接拼接历史应用源码；历史应用仅作为需求和运行证据。
5. 文件归档严格执行《网盘映射管理与文件命名规范》最新正式版。
6. 菜单使用四级规则：1 级业务大类、2 级模块、3 级事项、4 级科目；1 级只折叠 2 级，禁止 5 级。
7. 应用业务通知由来源应用自己的对应租户飞书机器人投递，统一通知汇总由与光工作中台承载；通知点击回到来源应用具体办理页。
