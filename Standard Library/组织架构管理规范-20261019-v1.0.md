# 组织架构管理规范

- **版本**：v1.0（2026-10-19）
- **状态**：正式版
- **适用范围**：与光工作中台及其接入的工具、项目和经营实体应用

## 一、组织架构唯一来源

轻立方租户的飞书通讯录是公司组织架构的唯一主数据来源和轻立方侧人员入口。姓名、电话、部门、邮箱、user_id 等主身份字段由轻立方飞书同步。与光工作中台是统一应用，承载完整的统一组织架构视图，并保留每个人的租户来源、登录入口和业务归属；应用不另建第三套组织主数据。

望向山、特产店（原规范称“特产馆”）、旅拍馆三家经营实体应用由与光租户承载。三家实体的组织归属映射到轻立方 **业务部 → 经营部**，但望向山的业务正式档案仍归档在与光租户的“望向山中台网盘”，不归档到轻立方网盘。与光租户组织节点通过映射纳入工作台统一组织架构，不形成互相割裂的应用组织。

## 二、组织树

```text
轻立方
├── 综合部
├── 业务部
│   ├── 项目部
│   └── 经营部
│       └── 经营实体映射节点（详见与光租户组织树）
└── 品牌部
```

与光租户组织树为：

```text
与光租户
└── 经营部
    ├── 望向山
    ├── 特产店
    ├── 旅拍馆
    └── 外协部（虚拟部门）
```

以上节点全部映射到轻立方“业务部 → 经营部”。外协人员在与光租户“经营部 → 外协部”下登录应用，轻立方侧保留对应的“业务部 → 经营部 → 外协部”映射节点。

望向山即咖啡厅，是同一经营实体的两个称呼；特产店为此前规范中的“特产馆”。三家实体业务组织映射到轻立方经营部，但望向山正式档案只进入与光租户“望向山中台网盘”。

镇安真味区域公用品牌项目管理中台属于特大项目专项管理，组织归属为轻立方 **业务部 → 项目部**，不属于经营部或经营实体。

## 三、花名册与租户规则

1. 花名册只有一份，通过“租户来源”字段区分轻立方、与光及外协来源；与光工作中台提供完整统一组织架构视图。
2. 两个租户共用同一员工编号序列，不因租户分开编号。
3. 轻立方优先：已在轻立方占位的员工通过轻立方登录；与光租户人员通过与光登录入口；登录入口、租户来源和业务归属分别记录。
4. “双租户数据合并”是跨租户主数据合并操作，仅创始人可以执行；其他人员禁止执行，避免业务数据混淆。
5. “应用内跨租户协作”是同一与光工作中台内的授权协作，不等同于数据合并；轻立方人员和与光人员可以在同一应用内按角色、项目、实体或事项协作。
6. 与光租户组织节点映射到轻立方经营部，工作台维护统一视图，不把与光租户作为无关的第二套业务组织。
6. 员工编号重复、缺失、格式错误或租户冲突进入异常队列，由人力确认处理，不自动覆盖。
7. 普通员工可查看本人、本部门及下属部门的基础信息，无需额外授权；花名册全量查看和全字段导出仅限创始人、部门负责人-人事、部门经办人-行政。
8. 默认花名册视图为在职员工，可切换离职、全部和历史快照。

## 四、同步与生效

- 飞书 `user_id` 是账号绑定唯一键，手机号只作同步字段和人工核对依据。
- OA 审批通过后的员工状态和组织权限以单据生效日期为准；无生效日期时以审批通过时间为准，并同时记录两者。
- 飞书字段回飞书修正；中台业务字段由人力发起更正，保存变更前值、变更后值、原因和操作人。
- 离职同步后立即撤销日常访问权限，保留花名册、历史业务档案和不可删除的变更历史；敏感档案仅授权角色可查。
- 所有组织、职位、员工编号、合同和敏感字段变更永久保留版本，禁止物理删除。

## 五、组织角色

| 层级 | 角色 | 说明 |
| --- | --- | --- |
| 公司 | 创始人 | 全量查看、配置、授权和最终确认 |
| 部门 | 部门负责人 | 对本部门业务结果负责，可确认本部门发布内容 |
| 部门 | 部门经办人 | 按职责办理日常工作和数据维护 |
| 部门 | 部门成员 | 本部门授权范围内执行工作，拥有点对点授予的部分编辑权限 |
| 部门 | 部门协作人 | 跨部门参与指定事项，权限按事项授权 |
| 部门 | 模块观察人 | 外部投资人、顾问、外协等只读人员，点对点授权 |

应用角色与组织角色同时存在：组织角色决定默认范围，应用授权角色决定具体项目、实体、模块和科目权限。观察人保留为外部只读角色，不作为普通员工的默认称呼。

## 六、应用内授权角色映射

### 与光工作中台

创始人全量；模块负责人；模块经办人；模块成员；模块协作人；模块观察人。人力、行政、财务、项目、经营等角色可以交叉协作。

### 灯塔知识库

创始人全量；公司成员按部门及所授权的应用、项目获得知识节点查看权限。知识节点权限不得反向改变组织架构。

### 与光品牌中枢 / 品牌生产中枢

创始人全量；品牌部负责人和成员拥有生产工具高权限；其他公司成员按授权使用工具，不默认拥有品牌资料管理权限。

### 星窗工作台

创始人、品牌部负责人、项目部负责人及被授权的商务人员可登录管理；普通员工不能登录管理端。项目参与人通过分享链接查看自己被授权的项目页面。

### 项目中台

创始人；项目负责人；项目经办人；项目成员；项目支持（人力、行政、财务、法务、经营）；项目观察人。项目负责人和经办人可不同；项目成员是项目执行人员；观察人只读。

### 经营中台

创始人；经营负责人；经营经办人（主理人是经营经办人的一种称呼）；经营协作人；经营成员（实体员工，即店员）；经营支持（人力、行政、财务、法务、品牌）；实体观察人。实体主理人属于实体经办人，不是独立组织层级。

## 七、权限原则

1. 组织架构授权解决“我属于哪里”；应用授权解决“我在这个应用/项目/实体做什么”。
2. 默认最小权限；跨部门协作、项目成员、实体成员和观察人均按点对点或明确范围授权。
3. 敏感字段按字段分级：本人查看本人相关信息；人力按职责查看；财务按核算/发放职责查看；创始人全量查看。
4. 敏感附件下载需额外点对点授权，记录用途、版本、时间和下载日志。
5. 授权、撤销、同步失败和异常处理均保留审计记录。
