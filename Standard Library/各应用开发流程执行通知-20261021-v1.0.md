# 各应用开发流程执行通知

- **版本**：v1.0（2026-10-21）
- **用途**：复制到各应用开发对话，要求该对话按《应用开发流程规范-20261021-v1.1》执行。
- **执行边界**：本通知是开发流程指令；业务规则仍以 Standard Library 中最新已批准的业务规范为准。

## 可直接复制的通知提示词

```text
【各应用开发流程执行通知】

请从现在开始按《应用开发流程规范-20261021-v1.1》推进本应用工作。执行前必须先完整读取该规范原文：E:\company-apps\Standard Library\应用开发流程规范-20261021-v1.1.md；如读不到或与本通知不一致，先报告差异，不得凭记忆或摘要执行。开始前先读取项目 AGENTS.md、Standard Library 中适用的最新规范、项目进度板、Git 状态和近期提交；不要假设压缩上下文或旧对话内容就是当前事实。

我的开发路线已经确定：

1. 由 Codex 在当前项目内完成适用的 Superpowers 工作链，包括现状核对、需求澄清、设计/spec、实施计划、隔离开发、按计划验证、评审和交接准备。Superpowers 是技能集合，不要求凑成固定“10阶段”；项目可按本规范映射记录阶段。
2. 由 Codex 先实现一个基础可操作 Demo，用来验证核心业务流程和需求理解。Demo 可以使用明确标注的本地模拟数据/接口，但不得把模拟能力说成真实系统集成。
3. 优先做本地、线下测试。先核验启动、核心流程、权限、数据状态、错误场景和适用的自动化测试，记录真实命令、输出、问题和未验证边界。
4. Demo 评审通过后，将已批准规范、需求/spec、实施计划、Demo 位置和测试记录、限制/风险、验收清单、Git 状态及下一步，整理成交接包，供我交给指定顶级模型（可为 Codex、Claude Code 或其他模型）完成正式实现。
5. 顶级模型完成正式实现后，先做本地构建和回归；只有确有必要且环境已准备时才进入测试/预发布部署。之后是否重新部署生产环境由我决定。

重要要求：

- 不要催促我线上部署，不要把线上部署当作当前目标、Demo 验收条件或阶段完成条件。默认优先本地测试和可审查的交付物。
- 除非我明确提出部署/上线，否则不要操作线上服务器、生产数据、生产通知或其他真实外部服务。可以提供发布计划供我审阅，但不要执行。
- 我遇到部署阻塞时，先帮助我缩小问题、恢复本地可运行/可验证状态、记录阻塞原因和回退方案；不要不断建议重新部署或用线上部署替代本地诊断。
- 不因追求完整而虚构 application_id、负责人、租户映射、接口凭证、压力目标、测试结果或云端验证结果。未知项明确标为待确认/未验证。
- 按现有正式规范执行统一员工 ID、双租户身份、批准接口、来源应用业务办理/机器人、通知深链权限校验、任务规则、网盘映射和审计要求；发现冲突先报告问题、影响范围及建议，不自行改业务规则。
- 模块边界要清楚，避免只交付漂亮前端。正式实现需覆盖真实业务逻辑、持久化/接口边界、权限、错误处理、日志、安全、部署配置和云端风险；Demo 模拟层不能冒充这些生产能力。
- 模型和供应商应可替换。AI/第三方能力经接口或适配器隔离；更换模型后重新核验结构化输出、提示词兼容、错误处理、测试和安全边界。
- 每个阶段结束、交接、暂停或恢复时更新项目进度板及交接记录，并写后读回核验。每次报告区分已确认事实、决策、建议、未知和验证证据。
- 关键业务规则不明确时一次只问我一个必要问题；不要把沉默视为批准。与当前工作无关的问题不要阻断独立可做的本地验证。

请先回复：当前阶段、你核验到的项目事实、适用规范版本、Git/进度板状态、已知未知项，以及下一项最小可验证工作。然后按规范继续，不要先做线上部署。
```

## 使用说明

发送前将应用特定信息（应用名称、代码仓库、当前模块和目标 Demo）追加到提示词末尾。不要附加密钥、访问令牌或生产凭证。若应用存在已批准的特殊规范，以该规范的具体业务条款为准，并记录规范名称和版本。
