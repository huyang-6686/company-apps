# 任务接口合同

- **版本**：v1.0（2026-10-20）
- **状态**：正式版
- **服务提供方**：与光工作中台
- **服务使用方**：已接入的工具、大项目和经营实体应用

## 一、接口原则

与光工作中台是任务主数据和权限校验中心。应用不得直接读写工作台或其他应用数据库，只能调用本合同接口。所有请求必须携带 `application_id`、调用方身份和幂等键；所有返回任务必须执行调用方应用授权过滤。

### 1.1 支出意向登记轻审批事件

“支出意向登记”作为独立轻审批对象接入本合同的通知、待办、逾期和审计能力，不作为普通任务类型或普通任务状态存储。来源应用提交轻审批对象及其业务关联，工作台负责统一员工 ID、租户、应用、项目/实体授权校验和事件汇总；具体办理页仍由来源应用或与光工作台提供。

轻审批事件至少应携带：`intention_id`、`application_id`、`tenant_id`、`applicant_employee_id`、`category`、`project_id` 或 `entity_id`（按来源必填）、`estimated_amount`、`need_by`、`urgency`、`first_approver_employee_id`、`approval_deadline`、`procurement_method`、`procurement_executor_employee_id`、`procurement_expected_at` 和 `settlement_method`。其中 `settlement_method` 取 `employee_reimbursement`、`company_payment` 或 `third_party_paid_no_settlement`；第三种方式直接记为“已结清（登记）”，不要求付款 OA 单号。

轻审批事件必须支持：发起、待审批、审批通过、审批驳回、退回补充、逾期升级、采购完成、采购逾期、收货确认、结算登记和撤回。首位负责人 1 个工作日未处理时产生升级事件；创始人接手后的处理是最终审核，不重复生成会签节点。事件去重使用 `intention_id` 与事件幂等键，不得因统一通知汇总重复生成业务记录。

## 二、核心对象

| 字段 | 说明 |
| --- | --- |
| `task_id` | 工作台生成的全局任务 ID |
| `parent_task_id` | 来源任务 ID；接收人重新下发或协作时填写 |
| `application_id` | 任务所属应用 ID |
| `module_id` | 模块 ID，可为空；为空显示应用通用 |
| `task_type` | `daily`、`operation`、`project` |
| `publisher_id` | 发布人员工 ID |
| `assignee_id` | 接收人员工 ID |
| `collaborator_ids` | 协作人 ID 列表，可为空 |
| `collaborator_department_ids` | 协作部门 ID 列表，可为空 |
| `status` | 任务状态，见任务规范 |
| `due_at` | 截止时间，ISO 8601 |
| `version` | 任务内容版本号，每次修改递增 |
| `source_tenant` | 来源租户标识，仅用于身份和审计 |

## 三、同步接口

### 3.1 创建任务

`POST /api/task/v1/tasks`

工作台内部完成应用、模块、接收人和发布权限校验后创建任务。应用不得绕过工作台创建任务。

### 3.2 查询任务

`GET /api/task/v1/tasks?application_id=&module_id=&status=&updated_since=`

返回调用方有权查看的本应用任务。分页使用游标，应用不得通过修改筛选参数突破权限范围。

### 3.3 获取详情

`GET /api/task/v1/tasks/{task_id}`

返回任务字段、当前权限可见的附件索引和审计时间线。

### 3.4 提交接收确认

`POST /api/task/v1/tasks/{task_id}/accept`

接收人确认收到后，工作台将状态置为 `in_progress`。

### 3.5 提交反馈和结果

`POST /api/task/v1/tasks/{task_id}/completion`

请求包含 `description`、`completed_at`、`attachment_ids`。工作台将状态置为 `pending_acceptance`，发布人验收后进入 `completed`，驳回则回到 `in_progress`。

### 3.6 验收或驳回

`POST /api/task/v1/tasks/{task_id}/acceptance`

请求包含 `approved`。当 `approved=false` 时，`reason` 必填；工作台记录操作人、原因和时间。

### 3.7 更新任务

`PATCH /api/task/v1/tasks/{task_id}`

仅发布人或授权管理员可修改标题、描述、优先级、截止时间、协作要求和附件。每次修改必须携带当前 `version`，版本冲突返回 `409 TASK_VERSION_CONFLICT`。

### 3.8 取消任务

`POST /api/task/v1/tasks/{task_id}/cancel`

请求包含必填 `reason`。仅未完成任务允许取消。

## 四、事件回调

应用必须提供 HTTPS 回调地址并验签，接收以下事件：

| 事件 | 触发 |
| --- | --- |
| `task.created` | 任务发布到应用 |
| `task.updated` | 任务内容或截止时间修改 |
| `task.accepted` | 接收人确认收到 |
| `task.completion_submitted` | 接收人提交反馈和结果 |
| `task.accepted_by_publisher` | 发布人验收通过 |
| `task.rejected` | 发布人驳回并填写原因 |
| `task.cancelled` | 发布人取消 |
| `task.overdue` | 任务进入逾期状态 |
| `task.reassigned` | 离职/调岗自动转派 |

事件结构：

```json
{
  "event_id": "evt_xxx",
  "event_type": "task.created",
  "occurred_at": "2026-10-20T09:00:00+08:00",
  "task_id": "tsk_xxx",
  "application_id": "app_xxx",
  "version": 1,
  "payload": {}
}
```

应用必须按 `event_id` 幂等处理，先返回 2xx，再异步完成业务更新；失败事件由工作台重试并提供补偿查询。

## 五、权限和错误码

工作台在每个接口执行组织、应用、模块、任务可见范围和操作权限校验。常见错误码：`401 UNAUTHORIZED`、`403 TASK_FORBIDDEN`、`404 TASK_NOT_FOUND`、`409 TASK_VERSION_CONFLICT`、`422 INVALID_TASK`、`429 RATE_LIMITED`。

## 六、文件和安全

附件上传使用工作台颁发的短期上传凭证，完成后回传 `file_id`。应用不保存任务附件永久副本，不把附件 URL 写入公开日志。所有请求、响应摘要、权限判定、重试和回调结果写入审计日志；日志不得包含访问令牌和附件敏感内容。

## 七、联调验收

接入应用必须通过：创建/查询/详情、接收确认、反馈提交、验收驳回、修改并发冲突、取消、逾期、自动转派、权限越权、事件重复投递和断线补偿测试。

任务相关通知遵循《统一信息通知与应用消息通道规范-20261020正式版》：任务事件进入统一通知中心，由任务所属应用的对应租户机器人投递；通知深链必须打开本应用具体任务办理页，不跳转到与光工作台代办。
