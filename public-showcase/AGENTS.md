# 星窗工作台 Git 协作规范

星窗是唯一对公网出口。它只接收审核后的脱敏内容，不承载内部台账、内部凭据或内部数据库。

## 进度与上下文纪律

- 每次回复末尾报告：`阶段：<名称> | CTX：statusline / 未检测 | 建议：继续 / 收尾 / 切换对话`。不得虚构上下文百分比。
- 任务完成并通过审查、用户要求继续/恢复/交接、或发现上下文可能丢失时，更新 `.project-board/state.json`、`board.md` 和 `events.jsonl`。
- statusline 超过 70% 时，不开始新任务；先收尾并更新进度板，再建议切换对话。
- 进度板缺失时，依据 Git 状态和可验证记录恢复，不猜测任务状态。

遵守仓库通用规则：Codex 默认实现，Harness 只读审查；任务独占写入权；使用 `task/<编号>-<短名>` 分支和独立 `.worktrees/<任务名>`；合并前必须完成测试、敏感信息扫描和人工审查。

内向星窗的投递只能经过明确的白名单字段和审核流程；公网回执只能包含批准的链接、状态和反馈字段。任何新的通信通道先写接口合同和威胁边界，再实现。
