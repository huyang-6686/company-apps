## 2. Demo 范围与可操作验收

Demo 以显眼横幅和 API 响应标识 `Demo 模拟数据 / 模拟接口`。提供种子数据和重置操作，可通过 UI 完成：

1. 在独立的“来源模拟器”页面准备候选内容；模拟来源应用执行审核和脱敏；审核拒绝仅留在来源模拟器，不向星窗发送。批准后来源模拟器生成带批准/脱敏声明的模拟签名请求。
2. 星窗接收接口仅接受已登记 allowlist 来源提交的“已批准且已脱敏”载荷；成功接收后状态为“已接收”。星窗没有审核页面、审核 API、审核前草稿或拒绝留存状态。
3. 管理操作员从已接收内容创建发布版本，并创建一个或多个分享链接；链接可选择公开链接、密码链接或仅内部访问。链接固定绑定一个星窗内容版本。
4. 公开访问统一走 `/share/[token]`。成功访问仅展示批准字段；密码错误、链接不存在、已撤销、已过期、内容不可用都返回同一不可用状态，不显示原因、不跳转。
5. 管理操作员可以撤销单个链接、重置其密码、撤销/下架内容版本；变更后同一链接立即不可访问。演示内容副本清理前仍不可访问；幂等最小记录保留。
6. 同一来源内容提交新版本时使用新幂等键与严格递增的来源版本号；新版本重新经过模拟来源审核/脱敏。旧版本链接始终绑定旧版本，不切换、不复活。
7. 所有主要访问页面支持手机视口；核心操作能用鼠标/触屏完成。

来源模拟器可展示“审核拒绝”结果，但该结果不进入星窗，也不属于星窗生命周期或回执。Demo 所有操作者均为假身份，页面不得声称真实集成。

## 3. 访问模式与权限矩阵

| 访问模式/角色 | Demo 表现 | 边界 |
| --- | --- | --- |
| 公开链接 | token 链接进入 `/share/[token]`，显示该链接绑定版本的批准字段 | 只可访问公开模式链接；不得按内容 ID 访问 |
| 密码链接 | 同一 token 路由先显示密码表单；正确密码才显示批准字段 | 不出现在公开列表、搜索、内容 ID 页面或公开元数据中 |
| 仅内部预览/来源身份授权 | 显示独立 Demo 登录/身份断言模拟页面；模拟创始人、品牌部负责人、项目部负责人、被授权商务人员、项目参与者及未授权者 | 只模拟最小授权判定；不接飞书、不推导真实租户映射。项目参与者只可见被授权的对应分享版本 |
| 管理操作 | 服务端 session 中的 Demo 操作员身份和角色决定读取、发布、撤销权限 | 客户端角色开关不是权限边界；未授权 API 请求拒绝 |

创始人可查看所有 Demo 管理内容；其他管理角色仅查看显式授予的模拟范围。项目参与者只读其模拟参与关系授权的分享版本；未授权角色拒绝访问。角色、范围和用户均为固定假数据，刷新后按 Demo session 规则恢复，不能据此证明真实身份系统或实际组织授权。

## 4. 模块与服务边界

- `src/app/(public)/page.tsx`：公开目录，只列当前有效、未过期、模式为 `public` 的链接所对应批准字段；密码/内部链接不得泄露存在性、标题或摘要。
- `src/app/share/[token]/page.tsx`：唯一公开分享访问入口；解析 token 哈希并执行链接、密码、版本状态及有效期校验。
- `src/app/admin/page.tsx`：受服务端授权保护的管理 UI：提交记录、已接收内容、版本、链接和审计时间线。
- `src/app/source-simulator/page.tsx`：星窗外部依赖的本地替身 UI，负责模拟审核、脱敏和已批准 payload 签名；审核拒绝仅在此页面显示。
- `src/app/api/receive/route.ts`：星窗模拟来源提交合同入口，只处理签名、allowlist、时间窗、nonce、schema、幂等和批准脱敏断言。
- `src/app/api/share-links/route.ts`：在授权管理 session 下创建分享链接。
- `src/app/api/share-links/[linkId]/revoke/route.ts`：撤销单链接。
- `src/app/api/share-links/[linkId]/password/route.ts`：重置/撤销单链接密码，使旧密码即刻失效。
- `src/app/api/content-versions/[versionId]/withdraw/route.ts`：授权撤回或管理员下线内容版本，记录原因并立即阻断其所有链接。
- `src/app/api/feedback/route.ts`：仅 Demo 本地接收反馈并调用失败可注入的 mock 转发适配器；不连接真实来源应用。
- `src/lib/contracts/`：来源提交、内外回执、错误类型的运行时 schema。
- `src/lib/services/`：提交接收、幂等、发布、分享访问、权限、审计和反馈服务。
- `src/lib/adapters/`：来源模拟器签名、Demo 身份断言、反馈转发 mock。
- `src/lib/repository/`：单进程本地 JSON 仓储；原子替换写入和进程内互斥；明确不可用于多进程/生产。
- `tests/`：单元、API 集成与访问矩阵测试。

不得创建 `/content/[id]` 公开页面或任何可绕过 share token 的公开 API。所有变更 API 都在服务端校验 session/来源签名和授权，不以隐藏 UI 控件代替访问控制。

### 4.1 展示导航

公开目录按已确认的三层展示方向组织筛选：第 1 层来源应用、第 2 层业务归属、第 3 层分享内容类型。Demo 只展示已存在有效公开链接的分组；空分组不显示。该分组是展示筛选结构，不新增组织主数据、不改变来源业务归属、不构成五级菜单。管理面可在同一页面查看提交、版本、链接和审计时间线，不复制来源应用办理页面。

## 5. 提交合同与幂等规则

### 5.1 Demo 来源 allowlist 与模拟签名

Demo allowlist 使用明确的虚构来源代号（例如 `demo-source-projects`），不称其为真实 `application_id`。每个来源只使用进程环境中生成的本地 Demo 测试密钥，仓库和日志只写 `[REDACTED_SECRET]`。来源模拟器通过 HMAC-SHA256 对规范化请求体签名，并提交 `X-Demo-Source-Id`、`X-Demo-Key-Id`、`X-Demo-Contract-Version`、`X-Demo-Timestamp`、`X-Demo-Nonce`、`X-Demo-Signature`。这是教学/流程替身，不是正式身份、凭证管理或生产签名合同。

接收端要求：来源 ID 在 allowlist；key ID 当前有效；时间戳与服务器 UTC 时间相差不超过 Demo 固定窗口 5 分钟；nonce 非空、未使用且在窗口内不可重放；签名常数时间比较；签名覆盖 method、path、timestamp、nonce、合同版本和规范化请求体。验签失败、来源未登记、时间窗错误、nonce 重放一律拒绝且不产生业务状态变化；响应只返回通用拒绝类别，不回显验签细节。

合同版本使用固定 Demo 值 `demo-content-v1`。schema 明列允许字段：`sourceContentId`、`sourceVersion`、`title`、`summary`、`approvedFields`、`approvedAt`、`approvalRef`、`redactionAttested`、`idempotencyKey`。未知字段拒绝；必填字段缺失、字段类型/长度/格式不合格、白名单外 `approvedFields` 拒绝。`redactionAttested` 必须为 true，来源审核引用必须非空。此标记只是模拟声明，不能证明真实审核或脱敏发生。

### 5.2 Submission 与永久幂等记录

`Submission` 为本地处理记录，状态限定为“已接收、处理中、已拒绝、已完成”。已拒绝仅表示星窗入口合同校验失败的通用处理结果，不含被拒载荷和审核状态；未批准/未脱敏载荷不创建内容版本或展示内容。

`IdempotencyRecord` 与内容副本分离，永久保留：幂等键、来源应用 ID（Demo 来源代号）、来源内容 ID、来源版本号、最终状态、首次接收时间、载荷哈希、原回执引用（星窗内容编号+版本号）。删除内容副本、附件/展示数据后仍保留该记录；不得保存正文、附件、展示字段或签名密钥。

载荷哈希：先按 RFC 8785 JSON Canonicalization Scheme 对 schema 允许字段规范化，再计算 SHA-256；签名覆盖同一规范化字节。未知字段在规范化前即拒绝。来源版本对同一来源内容必须唯一且严格递增，允许跳号；重复或倒退拒绝。一个新内容版本须使用新幂等键。

对 `sourceId + idempotencyKey` 唯一约束并在单进程仓储临界区内原子执行；以临时文件写入、flush 后原子 rename，并在同一临界区更新内容版本与幂等记录。并发冲突只允许一个新版本成功，其余读取已提交记录并按下表响应。Demo 为单进程；不声称多实例原子性。

| 情况 | 业务效果 | 内部结果 | HTTP |
| --- | --- | --- | --- |
| 新键、签名/schema/批准脱敏声明均有效 | 创建一个内容版本和永久幂等记录 | `accepted` + 原回执引用 | 201 |
| 同键、相同来源与规范化载荷哈希 | 不重复创建；返回原回执引用及当前状态 | `idempotent_replay` | 200 |
| 同键、载荷哈希不同 | 无变更 | `idempotency_conflict` | 409 |
| 内容副本已删除，原键、原载荷重试 | 不恢复正文；返回原回执引用（星窗内容编号、版本号、当前状态） | `deleted_payload_replay` | 200 |
| 内容副本已删除，原键、不同载荷重试 | 无变更 | `idempotency_conflict` | 409 |
| 未登记来源、签名失败、时间窗过期、nonce 已用、版本号不递增 | 无业务状态变更 | 通用拒绝类别；不得泄露签名细节 | 401/403/409 |
| 白名单/schema/合同版本/批准脱敏声明不合格 | 无内容版本；记录最小通用拒绝结果，不保存载荷 | `invalid_submission` | 422 |

星窗内部回执 schema：`receiptId`、`sourceId`、`idempotencyKey`、`contentId`（若已创建）、`contentVersionId`（若已创建）、`sourceVersion`、`status`、`resultCode`（通用类别）、`receivedAt`、`payloadHash`、`demo: true`。不得包含正文、附件、密钥、签名或详细验签诊断。

公网回执 schema 与内部回执分离，仅允许 `shareUrl`、`status`、批准的反馈入口字段、`demo: true`。不返回来源 ID、幂等键、载荷哈希、内部内容编号、拒绝细节或已删除正文。实际公网接口不在 Demo 范围；此 schema 用于约束模拟公开响应。

## 6. 内容版本、分享链接和生命周期

### 6.1 实体

- `Content`：星窗生成的 `contentId`、来源代号、来源内容 ID、创建时间及当前有效状态引用。
- `ContentVersion`：`contentVersionId`、`contentId`、来源版本号、批准字段投影、来源批准时间/引用、接收时间、状态、有效期、创建事件引用。新版本只由有效的已批准且脱敏来源提交创建。
- `ShareLink`：`linkId`、`contentVersionId`、模式（public/password/internal）、token 哈希、可选密码哈希、有效期、状态、创建角色/假用户、创建时间、撤销时间/原因、密码代次。token 使用密码学安全随机数，数据库仅存 SHA-256 token 哈希；明文 token 只在创建时显示一次，不进入日志。密码用 scrypt 哈希；不得记录明文密码。
- `AuditEvent`：事件 ID、动作（提交接收/发布/链接创建/链接撤销/密码重置/内容撤回/管理员下线/到期/副本删除/反馈接收/转发结果）、对象 ID 和版本、假操作人/角色或来源代号、时间、原因、请求关联 ID、最小数据来源。禁止记录载荷正文、附件、凭证、token 或密码。
- `Feedback`：反馈 ID、contentVersionId、匿名标志、可选联系方式、受限长度正文、接收时间、状态、mock 转发结果；不存凭证。

### 6.2 发布与新版本

内容副本在来源批准且脱敏声明通过接收校验后创建“已接收”版本；管理操作员显式执行发布动作才置为“已发布”。创建链接不等于发布。已到期版本不可直接恢复发布；来源必须按新版本提交规则重新审核并脱敏，使用新幂等键和更大来源版本号，再创建新的星窗版本并发布。旧版本链接永不切换到新版本，也不因新版本发布自动复活。

### 6.3 链接级控制

同一内容版本可创建多个 ShareLink。每条链接独立模式、token、密码、有效期、撤销状态。撤销链接只影响该链接；密码重置递增密码代次并使旧密码立即失效；撤销内容版本或来源撤销展示授权时，该版本所有链接即时阻断。内部模式链接不可由公开目录发现，必须通过 Demo 身份断言和授权范围校验。

### 6.4 有效期、撤销与下线

有效期默认长期；若设置期限，到期后访问检查惰性执行到期转换，并可由 Demo 刷新任务扫描补齐。到期版本/链接不再出现在公开目录；访问统一不可用。恢复展示必须由来源重新审核并以新来源版本号提交，不允许延长旧版本来规避重审。

来源撤销展示授权或要求下架、管理员发现异常并执行下线，均立即阻断相关版本所有链接和公开 API 响应；副本及附属数据按约定周期删除，清理前也不可访问。具体清理周期没有已确认数值，Demo 只提供可操作的“删除副本”按钮，不设置虚构期限。撤回、下线、到期和物理副本删除为不同审计动作；状态只使用已确认生命周期“已接收、已发布、已撤回、已下线、已到期”，删除通过副本存在状态/审计表示，不增加生命周期状态。

## 7. 公开访问、缓存与错误响应

- 唯一公开内容路由为 `/share/[token]`；token 不可预测且仅持久化哈希。不存在 token、撤销、到期、内容下线、密码错误、版本不可用均映射到同一外部响应结构和同一页面文案“内容不可用”，使用一致 HTTP 404；不返回失败原因、不跳转、不通过响应时长或元数据暴露链接存在性。
- 密码链接在通过密码验证之前不返回内容标题、摘要、来源、版本或内容长度等信息；密码挑战和结果使用 `Cache-Control: no-store`。重复错误密码限速为 Demo 内存窗口 5 次/分钟/IP，超限返回相同不可用响应；限速会在重启后清空且不代表生产抗攻击能力。
- 公开目录只可列具有有效 public ShareLink 的批准字段投影，不列密码或内部链接，不允许用 `contentId`、`contentVersionId` 查询公开内容。管理面按授权读取。
- 分享页面/API 设置 `dynamic = 'force-dynamic'`、`revalidate = 0`、`Cache-Control: no-store, max-age=0`；不静态生成、不使用 CDN/浏览器共享缓存。撤销后同一 URL 的下一次请求必须立即不可用。
- 所有 API 对授权失败执行服务端拒绝；变更 API 校验 session、角色、Origin 与 CSRF token。来源提交入口只接受模拟签名，不接受浏览器匿名请求。未授权请求不得产生状态或审计中的敏感数据变化。
- JSON API 均返回 `{ data?, error?: { code, message }, meta: { demo: true, requestId } }`。错误码至少包括 `UNAUTHORIZED`、`FORBIDDEN`、`INVALID_ORIGIN`、`INVALID_CSRF`、`SOURCE_NOT_ALLOWED`、`SIGNATURE_INVALID`、`REQUEST_EXPIRED`、`NONCE_REPLAYED`、`CONTRACT_VERSION_UNSUPPORTED`、`UNKNOWN_FIELD`、`INVALID_SUBMISSION`、`IDEMPOTENCY_CONFLICT`、`SOURCE_VERSION_CONFLICT`、`NOT_FOUND`、`RATE_LIMITED`、`STORE_ERROR`。公开分享失败始终归一为 `NOT_AVAILABLE`，不得透出内部错误码。

## 8. 反馈和手机端

反馈入口绑定当前 `contentVersionId`。允许匿名；联系方式可选；正文长度上限 2000 字符并按纯文本展示。星窗保存本地 Demo 反馈状态，再调用 mock 来源转发适配器；失败保留反馈与失败状态，不自动改投其他渠道，不包含敏感凭据。成功/失败结果仅对有权管理角色可见；公开端只返回批准的受理状态字段。真实来源入口、通知、机器人和反馈留存期限未提供，均未验证。

公开目录、分享页、密码输入页、内部预览和不可用页需在 360px、390px、768px、1280px 宽度下无横向溢出、主要操作可触达、正文可读。阶段4人工验收需用真实浏览器移动视口操作完整访问路径；若无移动设备，不得声称真机验证。

## 10. 明确不做与风险边界

本 Demo 不做：真实来源应用接入、真实申请/审核/脱敏、真实签名凭证或密钥轮换、真实 application_id/负责人/租户映射、飞书/与光统一身份或登录、真实项目参与关系、真实网盘访问/归档、通知中心/机器人/业务深链、OA/审批/工作流/任务、真实数据库/多进程并发/分布式锁、云端或生产部署、真实 HTTPS/域名/CDN/公网访问、压力容量保证、真实来源反馈转发、生产级速率限制/锁定/监控告警/备份恢复/安全认证。

Demo 假数据只用于单进程、本机与指定局域网演示；其他局域网设备可访问端口意味着变更操作必须通过服务端 Demo session 和 CSRF/Origin 检查，但该措施不构成生产安全认证。环境密钥仅本地生成，不提交、不输出。Next.js 构建目录 `.next/` 与 `.local-data/` 必须加入 `.gitignore`；本地仓储损坏时 fail closed 并保留现场，不自动重置业务文件。

未解决的正式系统问题继续作为未知项：真实来源 allowlist 与 `application_id`、批准字段和合同版本、签名/密钥注册与轮换参数、身份断言和授权范围、管理员/商务授权映射、反馈合同及留存期限、内容副本删除周期、正式并发/SLO 目标、实际飞书网盘目录 ID 与权限、负责人、部署拓扑。Demo 不对这些问题作业务裁定。
